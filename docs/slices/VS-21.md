# VS-21 — Pilot End-to-End Validation and Hardening

## Goal

Prove Kairo's already-approved V1 intelligence loop works coherently enough for a controlled pilot, and fix bounded defects that block that proof.

This slice validates existing product scope. It does not add new product capabilities.

## Requirements

`FR-01` through `FR-20`, only as already approved by `product/PRD.md`.

## Acceptance spine

The deterministic validation must prove, without requiring production credentials:

1. **Brand setup:** a Workspace/Brand can hold authoritative Brand Brain and approved source context without cross-Brand leakage.
2. **Discover:** sector-aware Hunter can return a useful Opportunity or explicitly return no strong opportunity; duplicates/filler do not pass silently.
3. **Research:** selected Opportunities retain source/evidence and Claim lineage, including uncertainty.
4. **Strategy/content:** candidate Angle/Campaign/Content Version lineage remains queryable through drafting and review.
5. **Truth/review:** unsupported Claims or prohibited content fail hard; revision remains bounded.
6. **Approval:** only the exact approved Content Version can become publishable.
7. **Creative media:** carousel/Reel generated media retains Brand, Content Version, Claim, source fingerprint, object/hash and encoder lineage.
8. **Publishing:** deterministic publish jobs keep media/options, idempotency and no-silent-success semantics.
9. **Metrics:** published-post lineage can receive supported/unavailable metric states without inventing data.
10. **Learning:** Performance Intelligence/Brand Learning emits cautious, evidence-linked next experiments rather than causal certainty.
11. **Isolation:** a second Brand cannot read/reuse another Brand's private context, generated media, publishing credentials, metric state or Learning evidence.
12. **Recovery:** safe retry/intervention states remain explicit for provider and workflow failure.
13. **Cost/latency:** the harness records bounded workflow/provider/model budgets where those boundaries already exist.
14. **UX contract:** primary web routes expose usable loading/empty/error/reconnect/retry states and preserve human approval authority.

## Proof sectors

The deterministic pilot matrix must cover the existing four proof sectors:

- AI / SaaS / Developer Technology
- Umrah / Religious Travel
- Motorcycles / Bikes
- IAS / UPSC Education

No proof fixture may contain real customer secrets or private production Brand data.

## Runtime strategy

Create a Kairo-owned **pilot journey verifier** that composes existing domain/worker/API seams with fakes at external network/credential boundaries. It must call actual Kairo runtime contracts rather than duplicate their rules in a separate toy model.

The verifier should emit a typed report with:

- scenario ID / sector / format;
- passed checkpoints;
- explicit unavailable/external checkpoints;
- failures with stable codes;
- elapsed duration;
- bounded cost/attempt metadata where available;
- lineage fingerprints needed to diagnose a failure.

CI must fail if any mandatory deterministic checkpoint fails.

## External-boundary rule

VS-21 may simulate the provider edge but may not claim a real production-provider smoke.

Real Auth0 callback, Meta App Review/credentials, live Instagram publication/Insights and deployed-environment smoke remain separate operational/release evidence.

## Allowed fixes

Fix defects discovered by the pilot verifier when they are:

- inside an already-approved FR-01…FR-20 behavior;
- within VS-21 allowed paths;
- compatible with existing architecture/security decisions;
- not a database schema, infrastructure, release-workflow or production-enable change.

If a blocking defect requires a protected path or a new product/policy decision, stop and record it instead of bypassing governance.

## Non-goals

- no new social channel;
- no autonomous publishing;
- no paid ads;
- no new AI/media provider;
- no OpenAlex/Crossref adapter;
- no live Marketing Lab or Brand skill activation;
- no migration;
- no infrastructure/release workflow change;
- no release, deployment or production enablement.

## Certification bar

Before exact-SHA certification:

- immutable install;
- clean PostgreSQL 18 migrations;
- production dependency audit;
- governance/preflight;
- full runtime verification;
- dashboard build;
- deterministic VS-21 pilot matrix all mandatory scenarios PASS;
- security review of cross-Brand, publishing, credential and media-egress boundaries;
- no unresolved blocking review threads.
