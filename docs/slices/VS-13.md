# VS-13 — Free Discovery Adapters

## Purpose

Implement the planned VS-12B phase: real free/public discovery providers behind the sector-aware Hunter foundation certified in VS-12.

## Requirements

- FR-06 Hunter / Discover
- FR-07 Duplicate and novelty intelligence
- FR-20 Pilot operations and controls

## Scope

Implement reusable provider/protocol adapters, not industry-specific Hunters:

1. RSS / Atom
2. Hacker News official v0 API
3. Bluesky public AppView
4. YouTube Data API

Integrate them through the existing generic Hunter source plans and Kairo ToolGateway boundary.

## Decision authority

DEC-009 governs provider and credential boundaries:

- official/public provider interfaces only;
- approved RSS/Atom feed configuration;
- no browser-cookie/session harvesting or unrestricted scraping;
- YouTube API key is optional infrastructure secret material and must not enter prompts, domain state or provenance payloads;
- missing credential/quota/provider failure degrades that provider without failing the whole Hunter run.

## Functional requirements

### Multi-source execution

The same Hunter must execute source-specific plans produced by `SourcePolicyResolver` / `SourceQueryPlanner`.

An explicit legacy query remains compatible and defaults to Agent Reach unless an explicit source is supplied by governed infrastructure.

### Provider isolation

A timeout, HTTP failure, malformed response, rate-limit or missing optional credential from one provider must not prevent remaining planned providers from returning evidence.

### Request budgets

Each provider must obey the Source Registry per-run query ceiling. Adapters must also bound internal HTTP fan-out and result count.

### Provenance

Every accepted evidence item must retain:

- canonical source URL;
- platform;
- provider identifier;
- provider version/API marker where meaningful;
- retrieval timestamp;
- published timestamp when supplied by the source.

### RSS / Atom

- generic feed adapter driven by approved feed definitions/tags, not sector-specific code;
- fetch only feeds relevant to the query tags when configured;
- cap response body size;
- reject unsafe/non-HTTP(S) feed URLs;
- parse RSS 2.x and Atom entries deterministically;
- normalize HTML/entity text;
- isolate malformed feeds;
- no XML external entity resolution.

### Hacker News

- use official `https://hacker-news.firebaseio.com/v0/` API;
- bounded list/item fan-out with cache support;
- deterministic query-term relevance filtering;
- ignore deleted/dead/non-story items;
- preserve source URL, using the HN item URL when no external story URL exists.

### Bluesky

- use public cached AppView host `https://public.api.bsky.app`;
- use `app.bsky.feed.searchPosts` public read path;
- no login/session required;
- cap results; handle 429/5xx as provider degradation;
- convert AT URI results to stable public post URLs where possible.

### YouTube

- use YouTube Data API `search.list` with `part=snippet` and `type=video`;
- API key supplied only to the adapter through a secret resolver/configuration boundary;
- no API key => provider unavailable, not Hunter failure;
- cap search calls according to the Source Registry and V1 daily budget policy;
- do not paginate in V1;
- normalize results to canonical `https://www.youtube.com/watch?v=<id>` URLs.

## Explicit exclusions

- OpenAlex / Crossref network adapters (next research slice)
- Meta/Instagram OAuth, Reels, carousel or Insights
- persistence schema/migrations for provider telemetry
- paid discovery/search aggregators
- browser automation or cookie/session scraping
- Paperclip in the Kairo runtime
- release, deployment or production enablement

## Acceptance criteria

1. AI, Umrah, Motorcycles and IAS source plans can execute through the same Hunter and provider router.
2. HN remains disabled for Umrah through the certified sector policy, not provider code branching.
3. RSS is one generic adapter usable with differently tagged feed definitions.
4. HN, Bluesky and YouTube produce normalized `DiscoveryEvidence` with provenance.
5. Missing YouTube key disables only YouTube.
6. One provider failure does not fail the multi-source Hunter run.
7. Planned query/request counts remain bounded.
8. Evidence is deduplicated across providers before model judgment.
9. Empty/weak discovery still produces zero opportunities rather than filler.
10. Deterministic fixture tests cover parsing, malformed responses, timeout/rate-limit handling and provider routing.
