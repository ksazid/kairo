# VS-20 — Publishable Creative Media Pipeline

**Status:** approved / implementing  
**Risk:** high  
**Implementation mode:** runtime-enabled outside production

## Goal
Close Kairo's generated-media execution gap by converting the existing VS-18 Reel render package into a bounded publishable MP4 and by issuing short-lived publishing-only HTTPS delivery URLs for generated Reel/carousel media without making private object storage public.

## Requirements
- FR-11 — Content Studio
- FR-13 — Approval workflow
- FR-15 — Publishing
- FR-20 — Pilot Operations and Controls

## In scope
1. Provider-neutral `ReelEncoderPort` with exact encoder-version provenance.
2. A deterministic FFmpeg adapter that invokes a configured binary directly with a fixed Kairo-owned argument grammar; no shell, arbitrary command, arbitrary filter or user-supplied process arguments.
3. Consume only the existing VS-18 Reel storyboard PNGs + canonical timed render manifest.
4. Verify every input artifact against its recorded SHA-256/content type before encoding.
5. Produce bounded `video/mp4` output and reject malformed/non-MP4 or oversized results.
6. Store the MP4 privately under a deterministic Workspace/Brand/source-fingerprint/encoder-version object identity.
7. Reuse an existing valid encoded object instead of re-encoding the same source+encoder version.
8. Add a publishing-media store/egress boundary that reads private objects by Workspace+Brand scope and issues publishing-only, short-lived HTTPS URLs.
9. Prepare generated carousel PNGs as ordered image `PublishMediaItem`s and generated Reel MP4 as one video `PublishMediaItem`.
10. Preserve source fingerprint, object ID, content hash, encoder version and expiry provenance through preparation.
11. Fail closed on scope mismatch, hash mismatch, content-type mismatch, stale/overlong URL expiry, unsafe URL, encoder timeout/failure or corrupted output.
12. Deterministic tests for cross-Brand isolation, idempotency, encoder argument confinement, input integrity and egress bounds.

## Explicit exclusions
- AI image/video generation;
- voice synthesis;
- stock-media search;
- arbitrary shell or command execution;
- user-controlled FFmpeg arguments/filters;
- Stories or mixed-video carousel expansion;
- autonomous approval/publishing;
- live Marketing Lab benchmark or Brand skill activation;
- API/database migrations;
- release, deployment or production enablement.

## Acceptance criteria
1. A valid VS-18 Reel package can be encoded through `ReelEncoderPort` into one bounded MP4 artifact.
2. The FFmpeg adapter never uses a shell and accepts only Kairo-generated frame files/timings plus fixed encoding arguments.
3. A storyboard or manifest hash mismatch prevents encoder invocation.
4. Output lacking an ISO-BMFF `ftyp` signature or exceeding configured size fails closed.
5. Encoded Reel object identity is deterministic by Workspace/Brand + source fingerprint + encoder version; an existing valid object is reused.
6. Carousel preparation preserves slide order and issues one short-lived HTTPS image URL per generated PNG.
7. Reel preparation issues one short-lived HTTPS video URL for the encoded private MP4.
8. URL issuance is scoped to the exact Workspace/Brand/object and bounded to the configured publishing TTL; unsafe/non-HTTPS URLs are rejected.
9. Cross-Brand reads/URL issuance cannot be converted into a successful preparation result.
10. No generated object is made public or treated as authoritative by URL.
11. Existing Instagram publisher receives the same `PublishMediaItem` contract and remains unchanged unless a regression fix is required.
12. CI, Security baseline, Product Intake, preflight and full runtime verification must pass before exact-SHA certification is requested.
