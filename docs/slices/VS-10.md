# VS-10 — Pilot Operations, Safety and Cost Controls

Status: Proposed for scope approval

## Goal
Provide tightly authorised internal controls to operate the Kairo pilot safely, diagnose failures and measure cost without creating an enterprise admin suite.

## Requirement IDs
- FR-20

## User-visible outcome
Authorised operators can inspect workflow failures/costs, retry safe jobs, disable problematic automation and record safety interventions with provenance.

## In scope
- Internal pilot operations views for Brand setup, Hunter, research, generation, Critic, publishing and metric failures.
- Safe retry/disable controls with authorisation.
- Model/search/tool/social cost accounting and workflow budgets.
- Manual intervention and safety-policy audit records.
- Operational health and failure telemetry.
- Access-control and audit tests for operator actions.

## Non-goals
- Customer-managed enterprise admin hierarchy.
- Unrestricted operator access to private content.
- Autonomous spend.
- Production deployment approval.

## Dependencies and gates
- Relevant upstream workflow states must exist.
- Operator authorisation is high-risk and requires security review.
- Sensitive content is not logged by default.
- Production release remains separately governed by exact-SHA PES approvals.

## Acceptance criteria
1. Unauthorised users cannot access pilot operations.
2. Operator actions are least-privilege and auditable.
3. Safe retries preserve idempotency and provenance.
4. Workflow/model/tool costs can be measured per Brand where applicable.
5. Problematic automation can be disabled without corrupting domain state.
6. The surface remains pilot operations, not a broad enterprise admin product.

## Governance
- Lifecycle: proposed.
- Implementation mode: specification-only.
- Scope, policy and implementation approvals remain pending.
- `.github/workflows/release.yml` remains protected.
- Superpowers begins only after the slice is approved/activated with runtime implementation permission.
