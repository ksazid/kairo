# VS-12 — Sector-Aware Hunter Source Routing

## Purpose

Extend the existing generic Hunter so approved Brand context selects relevant public discovery sources through deterministic, provider-neutral policy rather than industry-specific Hunter implementations.

VS-12 preserves the approved Kairo differentiation: Brand Context × Live Signals × Content Judgment × Performance Memory.

## Requirement traceability

- FR-03 — Brand Brain
- FR-04 — Knowledge and sources
- FR-06 — Hunter / Discover
- FR-07 — Duplicate and novelty intelligence
- FR-08 — Research dossier
- FR-20 — Pilot Operations and Controls

## Approved architecture

```text
Brand Brain
  -> Brand Intelligence Profile
  -> Sector Intelligence Pack
  -> Source Registry
  -> Source Policy Resolver
  -> Source Query Planner
  -> Generic Hunter
  -> replaceable DiscoverySourceProvider adapters
  -> Signals -> normalize/dedupe/cluster -> Brand relevance -> Opportunity
```

The existing `HunterOrchestrator`, provider-neutral discovery contracts, Signal provenance, novelty rules and `No strong opportunity found.` behaviour remain authoritative.

## VS-12A scope — routing foundation

VS-12A implements only the deterministic sector-aware routing foundation:

1. `BrandIntelligenceProfile` projection from existing approved Brand Brain fields where available.
2. Versioned `SectorIntelligencePack` configuration.
3. Deterministic `SourceRegistry` metadata and per-source request ceilings.
4. Pure `SourcePolicyResolver` producing `BrandSourcePolicy`.
5. Pure bounded `SourceQueryPlanner` producing provider query intents.
6. Four proof packs: AI / SaaS / Developer Technology, Umrah / Religious Travel, Motorcycles / Bikes, IAS / UPSC Education.
7. Compatibility with the existing Agent Reach discovery provider as fallback.
8. Unit/integration tests proving materially different source policies from the same resolver implementation.

## Explicit exclusions from VS-12A

- no RSS/Atom network adapter;
- no Hacker News network adapter;
- no Bluesky network adapter;
- no YouTube network adapter;
- no OpenAlex/Crossref network adapter;
- no unrestricted scraping, browser-cookie harvesting or session harvesting;
- no new external credentials or secret boundary;
- no Instagram publishing/Insights work;
- no web or API redesign;
- no persistence migration for a second authoritative Brand profile;
- no Paperclip runtime dependency;
- no release, production enablement or deployment.

External free-source adapters are reserved for VS-12B. Research enrichment is reserved for VS-12C. Instagram completion remains a separate ChannelAdapter follow-up.

## Design rules

1. One Hunter engine; never create sector-specific Hunter classes.
2. Provider adapters are organised by technical provider/protocol, not by industry.
3. Sector differences live in versioned configuration.
4. A disabled registry source cannot be enabled by a sector pack.
5. `weight === 0` disables a source for that policy.
6. Research/verification-only sources do not enter Hunter discovery query plans.
7. Query count is bounded by source registry ceilings.
8. Equivalent query intents are deduplicated before provider execution.
9. Brand excluded topics are removed before query generation.
10. Brand-private context may affect routing/scoring transiently but must not be copied into Global Intelligence source definitions.
11. Deterministic filtering and deduplication precede model-backed judgment wherever possible.
12. Existing model/agent budget ceilings remain unchanged.
13. Existing zero-filler behaviour remains intact.

## Proof-sector policy expectations

### AI / technology

- Hacker News high weight;
- RSS high weight;
- YouTube high weight;
- Bluesky secondary;
- Agent Reach fallback.

### Umrah / religious travel

- official/approved RSS highest;
- YouTube high;
- Agent Reach fallback;
- Bluesky low;
- Hacker News disabled exactly.

### Motorcycles / bikes

- automotive/manufacturer RSS high;
- YouTube high;
- transport/regulatory sources high;
- Agent Reach fallback;
- Hacker News low and only meaningful for software/EV-related intents.

### IAS / UPSC education

- official/government RSS highest;
- approved current-affairs sources high;
- YouTube medium/high;
- Agent Reach fallback;
- Hacker News near-zero/disabled unless explicitly configured.

## Acceptance criteria

1. The same resolver and Hunter implementation serves all four proof sectors.
2. Sector packs change source selection/weights without sector-name branching in resolver logic.
3. Hacker News is disabled for Umrah and highly weighted for AI.
4. Disabled registry sources override sector-pack weights.
5. Invalid source weights fail deterministic validation.
6. Query plans never exceed per-source request budgets.
7. Equivalent normalized query intents are collapsed.
8. Excluded Brand topics do not appear in planned queries.
9. Research-only and verification-only sources are excluded from Hunter discovery query plans.
10. Existing explicit-query Hunter callers continue to work.
11. No evidence still produces zero Opportunities rather than filler.
12. Evidence/source provenance remains mandatory.
13. Existing Agent Reach remains replaceable and can be disabled without rewriting sector logic.
14. No provider SDK/network call is introduced into domain routing code.
15. Brand-private context is not persisted into shared source definitions.
