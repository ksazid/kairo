# VS-84 — Guided Brand Onboarding and Shared Brand Memory Initialization

## Status
Scope and implementation direction v1.1 approved by the Product Owner on 2026-08-23. VS-84 is active and implementing. Certification, merge, release and production enablement remain separate exact-SHA gates.

## Outcome
A new or additional Brand starts from one public Brand URL, lets Kairo learn useful Brand context automatically, confirms a concise summary, and reaches Home without channel OAuth or a manual setup questionnaire.

The flow initializes the shared Brand Memory/intelligence layer approved in `DEC-010`. The one-public-reference onboarding and post-onboarding channel connection boundary are approved in `DEC-011`.

## Product rule

> Kairo never asks the user to perform a technical workflow Kairo can perform itself.

Onboarding is therefore a handoff to Kairo, not a provider/setup wizard.

## Approved user flow

```text
Paste one public Brand URL
  ↓
Kairo learns
  ↓
Confirm Brand
  ↓
Home
```

The normal first-value path is intentionally shorter than four user actions.

## In scope
1. Accept one public HTTP(S) Brand reference for both first-Brand and additional-Brand creation.
2. Support a Website, public social profile/content URL, product page, blog or another supported public page as evidence.
3. Infer a usable Brand name from the supplied reference when possible instead of asking for it first.
4. Create the Workspace only when the account does not already have one; additional Brands reuse the selected Workspace.
5. Reuse the existing public-reference reader, Knowledge Source and Brand Brain/shared Brand Memory model. Do not create onboarding-specific intelligence persistence.
6. Let Kairo infer evidence-backed Brand identity, audience, positioning, voice, content direction, visual direction and provisional goals.
7. Keep inferred goals under the hood during onboarding. They remain editable later from Brand.
8. Show one calm, truthful learning state while analysis runs; do not expose adapters, research jobs, provider scopes, retries or simulated technical stages.
9. Show a concise confirmation containing only useful summaries such as What you do, Who you serve, Your style and Main topics.
10. `Looks right` confirms the material inferred Brand fields shown by the simplified onboarding path and proceeds to Home.
11. Preserve the created Brand if public-reference learning is unavailable or limited; the user can still continue to Home and refine Brand context later.
12. Treat a public social URL as evidence only. It never grants publishing, private Insights or authenticated channel authority.
13. Move authenticated channel connection after onboarding to Home `Needs Attention` and Brand connection surfaces.
14. Reuse the existing capability-checked channel adapters, scopes and publishing approval rules when a channel is connected later.
15. Use the approved five-destination product navigation: Home, Content, Calendar, Results and Brand.
16. Apply the approved Kairo design baseline with purposeful short motion, responsive behaviour, accessibility and `prefers-reduced-motion` support.
17. Keep all primary onboarding interactions simple, mobile-usable and keyboard/screen-reader accessible.

## Under the hood
Kairo may perform public-reference retrieval, source creation, Brand Brain proposal generation, provisional goal inference, provenance validation and confirmation writes. These technical steps remain hidden unless a real user action is required.

AI-inferred fields remain evidence-linked until confirmed. Existing user-confirmed Brand facts cannot be silently overwritten by onboarding, imported context or later learning.

## Home handoff
After confirmation, Home becomes the next operating surface. A Brand without an authenticated publishing destination shows one plain-language `Connect a channel` item in `Needs Attention`. The item disappears when a suitable channel is connected.

## Motion requirements
Motion is feedback, not decoration.

- button press feedback is immediate and short;
- the learning state may use restrained progress motion;
- onboarding/confirmation surfaces may use subtle opacity/translation entrances;
- summary rows may reveal with a short stagger;
- normal UI motion should remain below about 300ms;
- no AI glow, confetti, decorative loops or animated primary navigation;
- reduced-motion mode must preserve understandable state changes without movement.

## Acceptance criteria
- [ ] A first-time user can create a Workspace + Brand from one public Brand URL without channel authentication.
- [ ] An existing user can add another Brand from one public Brand URL without recreating a Workspace.
- [ ] Kairo infers a Brand name from the public reference when possible.
- [ ] The supplied public reference is persisted through the existing Brand/source model and can be reused later.
- [ ] Evidence-backed Brand Brain proposals are generated without requiring the user to choose a primary goal.
- [ ] Provisional goals may be inferred but are not shown as an onboarding question.
- [ ] The confirmation surface is concise and does not expose technical workflow steps.
- [ ] `Looks right` confirms eligible inferred Brand context and routes to Home.
- [ ] Limited source/provider learning does not delete the Brand or force onboarding to restart.
- [ ] A public social URL cannot be mistaken for authenticated publishing/Insights access.
- [ ] A Brand with no authenticated publishing destination receives `Connect a channel` in Home Needs Attention.
- [ ] Existing channel adapters, scopes, tenant isolation and human publishing approval remain unchanged.
- [ ] Primary navigation is Home, Content, Calendar, Results and Brand.
- [ ] No separate Business Intelligence page, onboarding-only Brand-memory table or parallel source-of-truth model is introduced.
- [ ] Owner-confirmed Brand facts cannot be silently overwritten by inferred or learned context.
- [ ] The flow is keyboard accessible, screen-reader labelled, reduced-motion aware and usable at mobile widths without horizontal scrolling.
- [ ] Runtime/typecheck/tests/build, security baseline, governance validation and preflight pass before certification.

## Explicit exclusions
- channel OAuth/provider selection inside onboarding;
- a separate Business Intelligence product area or dashboard;
- new social providers or expanded Meta permission scope;
- autonomous publication;
- new Brand-learning acceptance policy;
- new analytics/attribution models;
- duplicate onboarding-specific Brand/source persistence;
