# VS-84 — Guided Brand Onboarding and Shared Brand Memory Initialization

## Status
Scope and implementation direction approved by the Product Owner on 2026-08-23. Runtime work starts only after the currently active VS-83 leaves the active delivery path.

## Outcome
A new or additional Brand can move from minimal setup to a usable, reviewable Brand context through one coherent onboarding journey. Kairo reuses the existing Website/Instagram/Facebook adapters, imports evidence, proposes Brand Brain context, and lets the owner confirm or correct material suggestions before they become authoritative.

The onboarding journey initializes the shared Brand Memory/intelligence layer approved in `DEC-010`; it does not create a separate Business Intelligence page or parallel data model.

## In scope
1. Keep first-Brand setup lightweight: Workspace name only when needed, Brand name, and optional website.
2. Present source connection as a clear guided step with Instagram recommended and Website, Facebook + Instagram, and Facebook available without forcing any source.
3. Reuse the same provider-neutral connection and Website adapters already used by Brand Brain refresh/reconnect flows.
4. Preserve partial progress across OAuth redirects and safe skips so users do not restart onboarding after a provider interruption.
5. Show bounded import/progress states for connected profile/source ingestion and Brand analysis.
6. Route imported evidence into the existing Brand Brain suggestion model rather than treating imported data as confirmed truth.
7. Present a focused review step for Identity, Positioning, Audience, Voice and Content Strategy suggestions, with confirm/edit controls.
8. Capture the owner-controlled primary objective and optional Brand boundaries during review.
9. Finish with a concise readiness state showing what Kairo learned, which sources are healthy, what still needs attention and one next action.
10. Apply the approved Kairo design baseline and UI UX Pro Max workflow: calm, content-first, responsive, accessible and progressively disclosed.
11. Keep Website and connected social sources available in Brand Brain for later refresh, reconnect, replacement or removal.
12. Do not duplicate Brand Memory, Learnings, source health or connection state in onboarding-specific persistence.

## Proposed user flow

```text
1. Brand basics
   ↓
2. Connect sources
   ↓
3. Kairo imports and analyses
   ↓
4. Review Brand suggestions
   ↓
5. Ready
```

### Step 1 — Brand basics
- first Workspace only: Workspace name;
- Brand name;
- optional Website URL;
- continue without requiring a Website or social connection.

### Step 2 — Connect sources
Primary recommendation:
- Connect Instagram Professional account.

Secondary options:
- Connect Facebook + Instagram;
- Connect Facebook only;
- Website remains optional and combinable.

The user may skip and connect later from Brand Brain.

### Step 3 — Import and analyse
Show truthful progress for the work Kairo can actually perform, for example:
- profile/source connected;
- recent content imported where permitted;
- Website/public source read where supplied;
- bounded visual/content analysis completed;
- suggestions being prepared.

Provider or source failure must produce a local recovery action without discarding the Brand or already saved evidence.

### Step 4 — Review
Group suggestions by:
- Identity;
- Positioning;
- Audience;
- Voice;
- Content Strategy.

Every material suggestion remains visibly `Suggested` until confirmed. The user can confirm, edit or leave it unconfirmed. Owner objective and Brand boundaries remain owner-controlled input.

### Step 5 — Ready
Summarise:
- confirmed Brand context;
- connected/healthy sources;
- unresolved suggestions or source issues;
- one primary next action, normally `Start creating` or `Explore ideas`.

## Acceptance criteria
- [ ] A first-time user can create a Workspace + Brand without connecting any external source.
- [ ] An existing user can add another Brand without recreating a Workspace.
- [ ] Instagram, Facebook + Instagram, Facebook and Website choices reuse existing adapters and connection boundaries.
- [ ] OAuth/source interruption does not delete the created Brand or force the user to restart completed onboarding steps.
- [ ] Connected/imported data remains evidence-linked suggestion input until the owner confirms material Brand Brain fields.
- [ ] Owner-confirmed Brand facts cannot be silently overwritten by imported or learned context.
- [ ] No separate Business Intelligence page, onboarding-only Brand-memory table or parallel source-of-truth model is introduced.
- [ ] Source health and one recovery action are visible when a connection cannot complete or refresh.
- [ ] The flow is keyboard accessible, screen-reader labelled and usable at mobile widths without horizontal scrolling.
- [ ] Existing Brand Brain refresh/reconnect/disconnect flows continue to work after onboarding completion.
- [ ] Tenant/Brand isolation remains enforced on every source, suggestion and confirmation action.
- [ ] Runtime, tests, security checks, UI review, governance validation and preflight pass before certification.
