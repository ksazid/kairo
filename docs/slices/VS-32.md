# VS-32 — Visual Content Calendar

## Goal

Upgrade the existing Brand Calendar into a calm, visual planning surface for FR-14 without changing publishing authority or introducing autonomous scheduling.

## Requirements

- FR-05 — Channels
- FR-10 — Campaign
- FR-13 — Approval workflow
- FR-14 — Calendar and scheduling
- FR-15 — Publishing

## User outcome

A user can quickly understand what is planned/published, move through time, filter the visible schedule, inspect destination/state, and take existing safe retry/cancel actions without navigating a dense enterprise-style scheduler.

## Scope

- Preserve the existing `/brands/:brandId/calendar` route and truthful publishing data.
- Add visual month calendar orientation and compact day cells.
- Add previous/current/next month navigation through URL search params.
- Add Campaign, channel and status filters using URL search params.
- Keep a chronological agenda representation for detail/actions and accessibility.
- Retain destination/account context and truthful states including scheduled, dispatching, published, failed, unknown, manual-required and cancelled.
- Preserve existing retry/cancel authority and server actions.
- Improve loading, empty, error, filtered-empty and reconnect/manual states.
- Make desktop/tablet/mobile behaviour explicit; mobile prioritises agenda and compact month orientation rather than a squeezed desktop grid.
- Use approved design tokens and existing Kairo product visual language.

## Non-goals

- No `Plan My Week` assisted scheduling.
- No drag-and-drop-only scheduling interaction.
- No autonomous approval/publication.
- No new social provider or OAuth flow.
- No analytics/performance ingestion.
- No production deployment or production enablement.
- No global redesign of unrelated Kairo screens.

## Design read

Authenticated SaaS planning workflow for lean multi-brand operators; calm, minimalist, content-first Kairo design family; medium information density; low ornamental motion; clarity and truthful publishing state over decorative calendar complexity.

## Acceptance criteria

1. Current month is obvious and Today/previous/next navigation is keyboard accessible.
2. A real month grid shows scheduled/published items on their correct dates without changing source data.
3. Campaign/channel/status filters can be combined and cleared through URL state.
4. Filtering never changes the underlying command state or publishing authority.
5. Status and channel meaning is communicated with text, not colour alone.
6. Existing retry/cancel actions remain available only for states already allowed by the publishing domain.
7. Empty calendar and filtered-empty states tell the user the next useful action.
8. Desktop/tablet/mobile layouts have no page-level horizontal overflow; mobile retains usable agenda/detail actions.
9. Focus states, semantic headings/labels and form controls remain accessible.
10. No production deployment, external publication or credential exposure occurs in this slice.
