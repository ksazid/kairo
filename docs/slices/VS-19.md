# VS-19 — Marketing Lab Shadow Execution

Status: Approved; implementing

## Goal
Execute a vetted pinned external marketing challenger in Kairo's Marketing Lab shadow stage against identical synthetic/public-safe benchmark cases, while preserving Kairo Native as the production baseline and all Kairo-owned truth, privacy, spend and publishing controls.

## Requirements
- FR-09 Angle development
- FR-11 Content Studio metadata/provenance
- FR-12 Drafter/Critic/Judge quality evaluation
- FR-16 Performance tracking
- FR-17 Performance Intelligence
- FR-18 Brand Learning
- FR-19 Experiments
- FR-20 Pilot Operations

## In scope
- A Kairo-owned shadow execution contract using the existing `AgentRuntimePort`.
- Exact verification of the challenger repository, commit, path and pinned content/blob hash before execution.
- A separately registered sandboxed shadow challenger derived from the vetted Corey `social` reference at `coreyhaines31/marketingskills@7868cb9251fad80a73d26e488a5ad5f6c4a9f335`.
- External reference text treated as untrusted strategy context, never system policy.
- `capabilities: []`, `maxToolCalls: 0`, bounded output/cost/timeout and no publishing authority.
- Synthetic/public-safe benchmark cases only; no private production Brand data.
- Paired Kairo Native versus challenger observation capture with provenance, truth result, quality inputs, latency and cost.
- Shadow-stage result may only produce existing Marketing Lab verdicts; it cannot auto-promote to live, qualified or Brand-selected execution.
- TDD coverage for source mismatch, prompt-injection-like content, secret-like fields, tool/publishing attempts, scope mismatch, invalid output and incomplete paired evidence.

## Explicit non-goals
- No arbitrary external package/code execution.
- No runtime network access for the marketing skill.
- No secrets or social credentials.
- No production Brand-context execution.
- No autonomous publishing or approval.
- No Brand skill selection/promotion.
- No live benchmark or real-world experiment.
- No UI/API/database migration.
- No release, deployment or production enablement.

## Acceptance criteria
1. Only a registered `sandboxed` challenger with `benchmarkStatus=shadow` is executable by the shadow service.
2. Source provenance must exactly match the pinned GitHub manifest and verified snapshot hash.
3. Shadow invocation has zero tools/capabilities and bounded cost/output/time.
4. External skill text is supplied only as untrusted reference context and cannot alter Kairo policy fields.
5. Production/private Brand data is rejected; benchmark fixtures are explicitly synthetic/public-safe.
6. Output must pass Kairo's typed output validator and Claim-lineage validation before becoming a benchmark observation.
7. Truth failure rejects the challenger regardless of marketing scores.
8. Shadow observations remain Brand/capability/format scoped and paired to the identical input fingerprint.
9. Shadow success can at most return `advance-to-live`; it does not create qualification or production selection.
10. No network, secret, publishing or infrastructure authority is introduced.
