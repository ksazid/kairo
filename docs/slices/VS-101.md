# VS-101 — Social and Video Source Intelligence Adapters

## Goal

Extend the shared SourceRouter with bounded YouTube, Instagram, Facebook and LinkedIn source adapters while preserving the Batch 1/2 Source Intelligence architecture.

## Acceptance criteria

1. YouTube video, Short and channel URLs are handled by a dedicated adapter ahead of generic HTTP fallback.
2. When an optional YouTube Data API key is configured, the adapter uses official public API metadata for videos/channels; when unavailable or quota-limited it degrades to bounded public-reference extraction rather than failing onboarding outright.
3. Instagram profile, post and Reel URLs are handled by a dedicated public-evidence adapter that uses the existing bounded public reader and records explicit extraction warnings when useful public evidence is unavailable.
4. Facebook Page, post and Reel/watch URLs are handled by a dedicated public-evidence adapter using the same bounded public reader and fail/degrade independently.
5. LinkedIn profile, company and post URLs are handled by a dedicated adapter rather than the generic website adapter; only public evidence is read and blocked/login-only pages produce explicit warnings/failure provenance rather than fabricated Brand data.
6. All four adapters emit `NormalizedSourceDocument` with canonical URL, source type, provider/parser versions, content hash, provenance, confidence and warnings.
7. Social adapters are registered ahead of Website and secure HTTP fallback; the existing secure HTTP/PDF reader remains the bounded public fallback used inside these adapters.
8. Tracking-only query parameters are removed for social/video source requests when safe, without removing semantic identifiers such as YouTube video IDs.
9. No private browser session, user cookies, scraped authenticated state or agent-visible provider credential is introduced.
10. Existing onboarding automatically uses these adapters through SourceIntelligenceBrandReferenceReader; no duplicate onboarding scraper is created.
11. Existing frozen UI, publishing authority, OAuth scopes and scheduler behavior remain unchanged.
12. Tests cover routing, success, optional-provider fallback, rate/quota degradation, blocked public pages, provenance and onboarding-reader reuse.

## Required evidence

- Focused adapter tests for YouTube, Instagram, Facebook and LinkedIn.
- Router-priority and secure-fallback tests.
- Social/video tracking canonicalization regression tests.
- SourceIntelligenceBrandReferenceReader integration tests.
- Full repository typecheck, tests, build, governance validation and preflight before certification.
