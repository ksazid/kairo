# VS-65 — Marketing Lab Truth and Five-Dimension Quality Evaluator

## Purpose

Close the machine-evaluation gap in Marketing Lab shadow qualification by producing Kairo-owned Truth and five-dimension quality evidence for already-collected synthetic/public-safe paired outputs.

VS-65 does not change Marketing Lab thresholds or advancement policy. It supplies the evaluation evidence that existing `MarketingBenchmarkObservation` records already require.

## Scope

VS-65 adds a blind pair evaluator that:

- evaluates two anonymized candidate outputs against the same approved benchmark case and supplied Claims;
- uses the existing Kairo `critic` role through `AgentRuntimePort`;
- grants zero capabilities/tools;
- uses synthetic/global-public scope only;
- applies one fixed Kairo rubric to both candidates;
- returns `truthPassed` and the existing five quality dimensions: `brandFit`, `hookQuality`, `originality`, `formatQuality`, `criticScore`;
- returns concise reasons plus model/runtime provenance;
- validates all scores in Kairo code before evidence can be accepted;
- never exposes candidate source/identity to the evaluator.

## Truth rule

Truth is independent of quality. `truthPassed` must be `false` when visible candidate content asserts factual, technical, experiential, quantitative, causal, model-specific or capability details that are not directly entailed by the supplied benchmark Claims.

Rhetorical framing may be creative, but it cannot smuggle in new factual support. The evaluator must use only the supplied Claims and benchmark context; external knowledge is not evidence.

## Quality rubric

Each score is an integer from 0 to 100:

- `brandFit`: fit to the synthetic benchmark Brand scope, audience, objective and stated opportunity; this is not a claim about a private production Brand voice.
- `hookQuality`: clarity, relevance and stopping power of the opening/cover hook without overclaiming.
- `originality`: useful non-generic framing while remaining grounded in supplied Claims.
- `formatQuality`: carousel structure, progression, scannability, slide coherence and CTA suitability.
- `criticScore`: holistic usefulness, clarity and persuasiveness subject to the Truth boundary.

The rubric and validation are candidate-neutral. No candidate can award its own scores.

## Bias controls

- Candidate inputs are labelled only `A` and `B`.
- Candidate source IDs, skill names and versions are not included in evaluator context.
- The same benchmark context and rubric are used for both candidates.
- Pair orchestration may alternate A/B placement by case to reduce systematic position bias before mapping results back to the source lanes.

## Explicit exclusions

VS-65 does **not**:

- fabricate or collect human preference scores;
- calculate human edit-distance evidence;
- change benchmark thresholds or default policy;
- return the final Marketing Lab advancement verdict by itself;
- activate VS-23 or VS-24;
- wire a production API or UI;
- apply migrations;
- deploy or enable production execution;
- grant network tools, credentials, social authority or publishing permissions.

## Acceptance criteria

1. Evaluator requests use role `critic`, global-public synthetic scope, zero tools/capabilities and bounded cost/time/output.
2. Candidate identity is absent from evaluator context; only labels A/B are visible.
3. The exact same rubric applies to both candidates.
4. Unsupported factual/detail assertions are explicitly required to fail Truth.
5. All five quality dimensions are present and bounded 0–100 by Kairo code.
6. Missing/malformed Truth, scores or reasons fail closed.
7. Evaluator provenance preserves runtime/provider/model/cost/latency metadata when available.
8. Certified Groq GPT-OSS structured output can enforce the evaluator response shape.
9. Unit tests cover request isolation, validation, malformed output rejection and strict schema routing.
10. No production deployment or benchmark/human-evidence execution occurs during implementation/certification.
