# VS-89 — Brand, Sources and Channels

## Goal

Bring the user-facing Brand experience into alignment with the approved Kairo design contract without changing the underlying Brand Brain, source-ingestion, OAuth, publishing or analytics domain models.

## Requirements

- FR-03 — Brand context remains inspectable and owner-editable.
- FR-05 — Channel connections remain understandable, least-privilege and recoverable.
- FR-18 — Accepted Brand learnings remain advisory and must not overwrite confirmed Brand truth.

## User-facing scope

### Brand

The primary Brand surface is named `Brand`, not `Brand Brain`.

It is organized into:

- Identity
- Audience
- Voice & Style
- Content Pillars
- Sources
- Channels

Avatar is intentionally not implemented in this slice because the repository currently has no presenter/avatar persistence or provider-binding contract. It will be a separate governed slice rather than a fake or dead-end UI.

### Inline-first editing

Simple Brand fields use local in-place editing:

- selecting the field/value opens the editor locally;
- Save updates that one field using the existing exact-version Brand Brain write contract;
- Cancel restores the displayed value locally;
- inferred/stale/confirmed state remains visible;
- saving an inferred value continues to convert it to owner-confirmed truth under the existing domain rule.

No separate Review & Control workflow is required for ordinary edits.

### Sources

Sources are evidence Kairo uses to learn the Brand. The Sources section may manage existing Website/link/private-note knowledge sources, health/status and enable/disable/remove actions.

Authenticated publish destinations must not be mixed into Sources.

### Channels

Channels are authenticated publishing and provider-Insights destinations.

The Brand → Channels overview uses existing channel-account and Meta connection-health contracts and shows:

- channel identity;
- selected account/page name;
- connection state;
- publishing capability summary;
- Insights/source-sync availability when supported;
- last verification/sync when available;
- one obvious Connect or Manage action;
- reconnect/disconnect recovery where appropriate;
- account groups only as progressive/specialist routing detail.

Normal UX must not expose tokens, app IDs or raw scope strings.

## Compatibility

- Existing `/brands/[brandId]/brain` remains the canonical Brand route for now; visible terminology is `Brand`.
- Existing `/brands/[brandId]/brand-brain-control` becomes a compatibility redirect back to Brand so old links do not expose the superseded form-first workflow.
- Existing specialist channel OAuth, selection and account-group routes remain available.

## Excluded

- Avatar/presenter persistence or generation.
- Settings → AI & Media Providers persistence/configuration.
- API, worker, migration, database, auth, token, provider-adapter, publishing or analytics-collection changes.
- Production deployment, release approval or production-enable.

## Acceptance

- Primary shell enters a user-facing `Brand` surface.
- Brand page has Identity, Audience, Voice & Style, Content Pillars, Sources and Channels entry.
- Editing is inline-first with local Save/Cancel.
- Confirmed vs Suggested vs Needs refresh is visible without relying on colour alone.
- Sources contains knowledge/evidence only.
- Channels has a dedicated overview and does not route users to Insights to manage connections.
- No raw scopes/tokens/app IDs appear in the normal channel overview.
- Existing Brand/source/channel contracts are reused unchanged.
- Responsive/accessibility/product-contract tests and repository CI pass on one exact SHA.
