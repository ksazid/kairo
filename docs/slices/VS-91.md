## In scope

### Shared authenticated shell

- Preserve exactly five primary destinations: Home / Content / Calendar / Insights / Brand.
- Keep Settings/Profile, Notifications and light/dark controls secondary.
- Preserve one Brand context in the shell; do not repeat Brand identity as a Home hero/scope card.
- Desktop sidebar remains quiet and approximately 240–248px.
- Mobile uses a quiet approximately 60–64px header and exactly five equal bottom-navigation destinations.
- Use one approved outline icon family and shared Kairo tokens/components.
- Remove normal-user navigation/entry points that expose legacy internal workflow machinery when they conflict with the approved shell.

### Shared visual primitives required by Home

- Inter typography and approved type scale.
- Approved neutral/semantic palette with restrained Kairo purple.
- 4px spacing grid, approved radii, thin neutral borders and subtle elevation.
- Shared buttons, icon buttons, inputs, textareas, status chips, cards, disclosures, loading/empty/error states and accessible focus treatment used by this slice.
- Reduced-motion behavior and touch/keyboard accessibility.

### Frozen Home

Implement the exact frozen Home reference and approved user-language contract:

1. Page title `Home` with supporting line: `What needs you, what to create next, and what Kairo is handling.`
2. Needs attention: one dominant actionable item, no duplicate notifications, plain `Retry` / `Fix` / `Review` actions where real.
3. My idea: large idea input plus truthful URL / Photo / Video / Media affordances, with `Get recommendations` as the primary action.
4. Kairo recommends the best supported format before durable creation begins; user can override supported format.
5. For you: horizontal recommendation cards with useful thumbnail, format badge, save/bookmark, title, concise rationale, truthful impact/fit indicator and `View all` where real.
6. What’s working: period selector plus Reach / Saves / Shares / Engagement rate and restrained trend/sparkline only when actual data exists.
7. Secondary Home sections from prior runtime (`Up Next`, `Continue`) must not be added merely because they exist in older implementation guidance if the final frozen Home reference does not show them. Existing underlying data/workflows remain intact and reachable through their canonical destinations.
8. No Research, Hunter, Angles, Campaign, Critic, Claims, provider mechanics, render IDs, version IDs or similar implementation vocabulary in the normal Home experience.

## Truthfulness rules

- Do not manufacture recommendations when confidence/data is insufficient.
- Do not show fake metrics, fake trends, fake readiness, fake connection or fake publishing states for visual similarity.
- Unavailable data must use the approved truthful unavailable/empty state.
- Photo/Video/Media affordances are rendered only when their actual path is supported.
- Existing evidence lineage remains under the hood/contextual disclosure and is not deleted from the domain.

## Existing safeguards preserved

- Workspace/Brand tenant isolation.
- Human approval before external publication.
- Exact approved content/version lineage.
- Provider credentials and OAuth authority remain server-side and protected.
- Public URLs do not grant channel/provider authority.
- Owner-confirmed Brand facts remain authoritative.
- Existing research/campaign/critic/claims lineage may remain internally but is not promoted in normal creator UI.
