### Batch 2 — Calendar and Results

### Batch 6 — Whole-product certification preparation

- Functionality Gap Register reconciliation.
- Evidence matrix for every frozen surface.

## UI-first functionality-gap rule

A missing ordinary backend/provider/data behavior must not remove, redesign or postpone an approved UI. Implement the approved surface now, render the truthful unavailable/not-configured/empty/disabled/degraded state, and record the behavior in the Functionality Gap Register in `product/UI-IMPLEMENTATION-CONTRACT-2026-08-25.md`.

Registered functionality gaps are not implemented in VS-91 until the complete frozen UI program has reached Milestone A (Frozen UI Complete). They become a later governed functionality phase.

## Explicit exclusions

- No Settings → Integrations implementation.
- No new backend/provider/publishing/billing/analytics behavior merely to make an approved UI look populated.
- No fabricated success, connection, provider health, publication, billing, source-health or analytics state.
- No redesign/regeneration of frozen surfaces.
- No reintroduction of rejected variants.
- No release, production enablement or production deployment.
- No modification of protected infrastructure, API/worker runtime or release workflow paths.

## Acceptance criteria

### Shared system

- Approved Inter/token palette/spacing/radii/elevation/icon discipline is consistent across frozen surfaces.
- Desktop shell is one 240–248px rail with exactly five primary destinations in approved order.
- Mobile bottom navigation is exactly five equal destinations with no `More` item.
- Mobile header exposes Brand/page context plus Notifications, light/dark and Profile/Settings utilities only.
- Persistent shell contains no unapproved floating/product-guide control or technical workflow destinations.

### Per surface

- Approved composition, controls, hierarchy and copy intent are present.
- No internal Research/Hunter/Angles/Campaign/Critic/Truth Gate/render/version/provider machinery leaks into normal user flow unless explicitly approved under specialist disclosure.
- Real unavailable states remain truthful and are registered when behavior is missing.
- Desktop and mobile visual evidence is captured before certification.
- Accessibility basics pass: labels, focus, keyboard path, semantics, contrast and touch targets.
- Existing working auth/data/route behavior is preserved unless an approved UI contract explicitly replaces its presentation.

### Program gates

- Deterministic type/test/build checks pass.
- `npm run governance:validate` and `npm run preflight` pass before readiness is claimed.
- Every frozen surface has an evidence-matrix PASS before UI certification.
- Functionality gaps are reconciled but remain a separate post-UI implementation phase.
