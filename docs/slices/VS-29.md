# VS-29 — Instagram Production Publishing Activation

## Goal

Make Kairo's already-certified Instagram connection and publishing contracts operationally deployable without widening publication authority: a dedicated executor may claim only Instagram publish commands, resolve only stored encrypted channel credentials, and execute the existing deterministic Meta publishing adapter.

## Requirements

- FR-05 Channels
- FR-13 Approval workflow
- FR-14 Calendar and scheduling
- FR-15 Publishing
- FR-20 Pilot Operations and Controls

## Dependencies

- VS-15 — Instagram Reel and Image Carousel Publishing
- Existing Meta Instagram OAuth/account connection implementation in `apps/api/src/instagram-connection*`

## In scope

1. Add a runnable publishing-worker entrypoint that uses the existing `PublishingJobRunner`, `InstagramProfessionalAdapter`, PostgreSQL execution store, and encrypted channel credential vault.
2. Ensure the production executor claims only Instagram commands and cannot consume unrelated LinkedIn/manual work.
3. Add bounded worker polling, lease and per-tick job limits with fail-fast configuration validation.
4. Build the publishing-worker entrypoint during normal API runtime verification.
5. Add a separate production Dockerfile/entrypoint suitable for a Render background worker.
6. Reuse the existing Meta Graph version and `CHANNEL_CREDENTIAL_ENCRYPTION_KEY`; do not create a second credential store or copy readiness credentials into production.
7. Keep the existing OAuth connect/callback/candidate/select/disconnect API route contract unchanged.
8. Add deterministic tests for configuration bounds, Instagram-only claiming behavior where practical, and secret-safety assumptions.

## Out of scope

- Connecting a real Instagram account in production.
- Copying or reusing readiness tokens/credentials.
- Publishing any real post, Reel or carousel.
- Automatic/agent-driven approval or publication.
- New social networks or LinkedIn worker activation.
- New database migrations.
- Meta app configuration changes.
- Production service creation, deployment, release or production enablement.
- UI redesign.

## Acceptance criteria

1. `npm run runtime:verify` builds both the API server and publishing-worker entrypoint.
2. The publisher requires `DATABASE_URL`, `META_GRAPH_VERSION`, and `CHANNEL_CREDENTIAL_ENCRYPTION_KEY` and fails closed on invalid/missing configuration.
3. Poll/lease/job-count settings are bounded and deterministic.
4. The publisher uses `PgEncryptedChannelCredentialVault` to resolve credential refs; plaintext tokens are never logged or persisted into publish jobs.
5. The publisher uses `InstagramProfessionalAdapter` and existing VS-15 unknown/retry semantics unchanged.
6. The publishing execution store can be restricted to `instagram`, and the production publisher uses that restriction.
7. Existing API/OAuth routes, single-image, carousel and Reel tests remain green.
8. No production credentials, account connection, deployment or publish command execution occurs during certification.
9. CI, Security baseline, Product Intake, governance/preflight and runtime verification pass before certification is requested.
