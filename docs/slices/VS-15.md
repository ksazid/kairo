# VS-15 — Instagram Reel and Image Carousel Publishing

## Goal

Make Kairo's existing deterministic Instagram publishing path work end-to-end for approved single images, Reels and image carousels, including persisted media descriptors and worker hydration.

## Requirements

- FR-05 Channels
- FR-13 Approval workflow
- FR-14 Calendar and scheduling
- FR-15 Publishing
- FR-20 Pilot Operations and Controls

## In scope

1. Persist typed media descriptors with a Publish Command instead of dropping media before worker execution.
2. Add explicit `reel` content type and `publish-reel` capability.
3. Preserve single-image Instagram publishing.
4. Publish one approved Reel from one public HTTPS video URL using Meta's container → status → publish flow.
5. Publish an image carousel from 2–10 public HTTPS image URLs using child containers → CAROUSEL parent → publish.
6. Persist bounded Instagram options including Reel `shareToFeed`.
7. Hydrate the exact media/options payload from PostgreSQL into `PublishingJob`.
8. Keep credentials behind `credentialRef`; tokens never enter domain state, API responses, logs or provenance.
9. Preserve existing unknown-outcome behavior: an uncertain publish result must not be automatically retried as if publication definitely failed.
10. Deterministic tests for validation, store hydration, provider requests, processing status, error handling and secret safety.

## Out of scope

- Instagram OAuth/account-connection UX
- Instagram Insights/metric ingestion
- mixed image/video carousels
- Stories
- media upload, transcoding, generation or rendering
- automatic/agent-driven publishing
- UI changes
- release, deployment or production enablement

## Acceptance criteria

1. A scheduled Instagram image command with one image reaches the worker with that exact media item.
2. A scheduled Reel requires exactly one video item and an account with `publish-reel`.
3. Reel container polling is bounded; only `FINISHED` proceeds to publish.
4. Reel processing `ERROR` fails safely and records provider correlation where known.
5. An image carousel requires 2–10 image items and `publish-carousel`.
6. Carousel child creation failure prevents parent publication.
7. Unsafe/private media URLs are rejected by the provider adapter before outbound publication.
8. Provider 429/5xx failures retain current bounded retry semantics; unknown publication outcomes remain unknown.
9. LinkedIn and existing Instagram single-image publishing behavior remain compatible.
10. No secret/token is serialized into domain, result or persisted media metadata.
11. PostgreSQL migration and clean migration verification pass.
12. CI, security baseline, Product Intake, governance/preflight and full runtime verification pass before certification is requested.
