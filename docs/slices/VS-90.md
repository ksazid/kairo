## Outcome

A Brand can keep one optional presenter profile that expresses how the Brand should appear and sound when a presenter is useful. Creation can explicitly choose that eligible presenter or `None`; `None` remains the default. Presenter intent is durable and Brand-scoped, but this slice does not pretend an avatar-rendering provider exists when none is configured.

## In scope

1. Add Brand-scoped presenter persistence with optimistic versioning and strict Workspace + Brand ownership.
2. Add authenticated API read/write contracts for the Brand presenter profile.
3. Add an optional `Avatar` Brand sub-surface, not a primary navigation destination.
4. Support the approved presentation modes:
   - Basic presenter
   - Talking avatar
   - Hybrid explainer
5. Seed an editable suggested setup from existing Brand context without silently converting suggestions into confirmed Brand truth.
6. Let creation choose an eligible Brand presenter or `None`; default is `None`.
7. Persist the optional presenter reference on the durable simple-creation request and return it in the creation view.
8. Fail closed when a presenter ID does not belong to the authenticated Workspace + Brand.
9. Show test/render capability truthfully. With no configured Avatar provider contract, test clip/rendering is unavailable rather than simulated.
10. Preserve all existing human review, approval, publishing, tenant-isolation and credential boundaries.

## Explicit non-goals

- No avatar video generation or test-clip provider execution.
- No MuseTalk or other provider hard-coding.
- No provider API keys, tokens, endpoint configuration or secret persistence.
- No worker/media-orchestrator changes.
- No automatic presenter selection.
- No face/voice cloning, biometric enrollment or raw identity-media upload.
- No change to approval locks, publisher behavior, Calendar, Insights or channel OAuth.
- No production deployment in this slice without later exact-SHA certification, release and production-enable approval.

## Data contract

`brand_presenters` stores one optional profile per `(workspace_id, brand_id)` with:

- stable `id`
- `display_name`
- `status`: `draft | ready | disabled`
- `mode`: `basic | talking-avatar | hybrid-explainer`
- descriptive presentation preferences: visual style, voice style, language/locale, accent, pace, framing, background, intro/outro style and caption preference
- integer `version`
- timestamps

No provider secret or raw biometric artifact is stored.

`simple_creation_requests.presenter_id` is nullable and references `brand_presenters(id)`. The service verifies the presenter is `ready` and belongs to the same Workspace + Brand before accepting it.

## API

- `GET /api/v1/brands/:brandId/presenter`
  - authenticated + Brand-authorized
  - returns `{ presenter, capabilities }`
  - current capabilities truthfully report avatar rendering/test clip unavailable until a real adapter is configured
- `PUT /api/v1/brands/:brandId/presenter`
  - authenticated + Brand-authorized
  - create or exact-version update
  - returns the saved presenter
- existing `POST /api/v1/brands/:brandId/simple-creations`
  - accepts optional `presenterId`
  - validates same Brand + Workspace and ready status

## UX contract

### Brand → Avatar

No presenter:
- compact explanation
- suggested profile derived from current Brand context
- editable presenter mode and presentation preferences
- primary `Create & Save`

Existing presenter:
- presenter summary first
- `Manage` / edit locally
- status can be disabled without deleting history

Provider capability:
- no fake Test Clip button
- explain that test/rendering becomes available only when an Avatar provider is configured through the governed provider settings path

### Creation

- Presenter selector appears only when the Brand has an eligible (`ready`) presenter.
- First option is always `None` and remains the default.
- The selector is contextual, secondary to goal/input/format.
- Choosing a presenter persists the selected ID on the durable creation request.
