# VS-63 — Instagram Publishing E2E Coverage Refresh

## Purpose
Refresh the legacy Instagram publishing end-to-end coverage in PR #88 onto current `main` and certify it against the retry semantics merged in VS-62.

## Scope
- Test-only coverage of the approved Instagram carousel publishing execution path.
- Verify one approved command is claimed once, decrypted credentials are used only at the adapter boundary, Meta calls are stubbed, settlement succeeds and one `published_posts` row is written.
- Verify a stubbed HTTP 500 is classified as retryable by the merged VS-62 adapter behavior, schedules exactly 30 seconds later, performs one provider call and writes no published post.
- Verify plaintext test credentials are not persisted in the encrypted credential table.

## Non-goals
- No runtime production code changes.
- No Meta/OAuth application, permission, credential or provider configuration changes.
- No database migration or production data mutation.
- No live Meta request or real account connection.
- No deployment, release, publication or production enablement.

## Acceptance criteria
1. PR #88 is based on current `main` behavior and remains limited to the approved test/governance paths.
2. The success path proves exactly-once publishing and encrypted credential handling.
3. The failure path proves the VS-62 30-second transient retry hint end to end and no published record on failure.
4. Product Intake, Security and full CI pass on the frozen exact candidate.
5. Merge remains separately owner-approved.
