# VS-61 — Content Asset Selection in Content Studio

## Goal

Let a creator attach already-indexed, Brand-scoped Content Asset Library items to an exact Content Version from Content Studio, without expanding provider access or weakening Kairo's exact-version review and approval model.

## User outcome

From a Campaign's Content Studio, a user can inspect available indexed production assets, select or clear up to 12 items for the current Content Asset, and save that selection as a new immutable Content Version. The selected metadata remains visible in version history even if the underlying library is later re-indexed or disconnected.

## Functional scope

1. Add immutable Content Library asset references to `ContentVersion`.
2. Add the `asset-selection` Content Version action.
3. Persist the exact selection snapshot with each Content Version.
4. Authorize every selected library asset against the authenticated account and target Brand before creating the new version.
5. Never accept provider/library provenance metadata from the client; the server builds snapshots from the indexed library records it can authorize.
6. Preserve selected references when a user makes a normal manual edit or requests an AI-assisted text transformation.
7. Changing or clearing selected references creates a new immutable version and therefore requires a fresh review/approval just like any other version change.
8. Add a calm, secondary `Production assets` disclosure in Content Studio with explicit selected state, searchable/filterable Brand asset choices, and a reference-only notice.
9. Keep selection metadata-only. No provider network call or file content fetch is needed for this workflow.

## Exact-version model

The selection belongs to `ContentVersion`, not the mutable Content Asset shell. This is intentional:

- Truth Gate, Critic and human approval are already bound to an exact Content Version.
- A changed production-asset set must not silently alter an approved version.
- Historical versions retain the exact asset provenance that was visible when they were reviewed.
- Re-indexing or disconnecting a Content Asset Library must not rewrite historical Content Versions.

## Reference snapshot

Each selected reference is server-generated and contains only non-secret metadata needed for provenance and display:

- `libraryId`
- `libraryAssetId`
- `libraryName`
- `provider`
- `externalId`
- `name`
- `kind`
- `mimeType`
- optional safe `providerRef`
- optional `previewRef`
- `indexedAt`

No access token, refresh token, OAuth state, encryption material, file bytes, or client-supplied provider metadata may be stored in the snapshot.

## Limits and validation

- Maximum 12 selected library assets per Content Version.
- Duplicate library asset IDs are rejected.
- Missing, stale or cross-Brand asset IDs fail closed with a safe not-found response.
- The Campaign, Content Asset, library and selected items must all belong to the same authorized Brand/workspace.
- `expectedVersion` is mandatory and uses the existing optimistic-concurrency boundary.
- A request that is an exact no-op is rejected instead of creating version noise.

## UX requirements

Follow `product/DESIGN.md` and UI UX Pro Max guidance:

- `Production assets` is contextual/secondary, not a new primary navigation destination.
- Selected items are represented with quiet rows/chips showing name, kind and source library/provider.
- The control has explicit text states; meaning must not depend on color.
- Empty library, no matches, selected, and validation/error states are distinct.
- The picker remains keyboard operable and responsive with no horizontal scroll.
- Copy must state that this step stores references only and does not download or publish Drive files.
- Existing Content Studio review, approval and AI hierarchy must remain intact.

## Acceptance criteria

- [ ] Existing Content Versions load with an empty asset-reference list after migration.
- [ ] Selecting one or more authorized indexed assets creates version N+1 with `action=asset-selection` and snapshots server-owned metadata.
- [ ] Clearing a non-empty selection creates version N+1 with an empty snapshot.
- [ ] A stale `expectedVersion` returns the existing concurrency failure.
- [ ] Cross-Brand/missing library assets cannot be attached.
- [ ] More than 12 or duplicate IDs are rejected.
- [ ] Manual edits inherit the previous selection.
- [ ] AI-assisted text transformations inherit the previous selection.
- [ ] Existing exact-version review/approval automatically ceases to represent the current version after selection changes.
- [ ] Persistence round-trips selected snapshots through PostgreSQL 18.
- [ ] Content Studio shows current selections and Brand-authorized indexed candidates without provider calls.
- [ ] Version history exposes the selected-asset count/provenance for each historical version.
- [ ] No Google Drive binary download, provider OAuth mutation, publishing action, Brand Brain mutation or deployment occurs.

## Non-goals

- Downloading, copying, transforming, OCRing or generating provider file bytes.
- Uploading selected assets to social providers.
- Automatically choosing production assets with AI.
- Google Drive OAuth/client configuration or new provider scopes.
- Drive watch/webhook synchronization.
- Brand Brain or Knowledge-source ingestion from Content Asset Libraries.
- New Content Asset Library providers.
- Changing Truth Gate, Critic or human-approval policy.
- Deployment, release or production enablement.

## Rollback

The database change is additive (`library_asset_refs`) plus an expanded action constraint. Rollback at application level is to stop emitting `asset-selection`; historical JSON snapshots remain non-secret inert metadata. Production database rollback is not authorized by this slice.
