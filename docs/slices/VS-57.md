# VS-57 — Operations + More / Secondary Management Design Remediation

**Status:** approved / implementing  
**Risk:** medium  
**Implementation mode:** runtime-enabled UI only

## Goal
Implement UI-06 from issue #94 so Pilot Operations is a task-first internal control surface and mobile `More` is a coherent secondary-management hub without expanding Kairo's primary navigation.

## Requirements
- FR-20 — Pilot Operations and Controls
- Approved `product/DESIGN.md` web/mobile information architecture and progressive-disclosure rules

## In scope
1. Move Operations to the shared `KairoProductShell` and mobile `More` state.
2. Make operational failures requiring retry/judgment the dominant first task.
3. Replace four competing summary cards with one quiet status line.
4. Order safe retries before manual-review and blocked failures without changing retry eligibility.
5. Progressively disclose budgets/measured cost, automation controls and audit history.
6. Preserve existing retry and disable-automation server actions and redacted diagnostics.
7. Add accessible progress semantics for workflow budgets.
8. Redesign `More` into grouped secondary navigation for deeper creation/review, Brand/channel management and internal pilot controls.
9. Keep Settings visibly deferred rather than inventing a route.
10. Allow the shared shell to represent a secondary page with no false desktop primary-nav selection.
11. Deterministic view-model tests for failure ordering, retry eligibility, attention counts and bounded budget progress.

## Explicit exclusions
- no API/domain/contracts/database/migration changes;
- no new operator capability or mutation;
- no change to retry/automation authorization, idempotency or audit semantics;
- no publishing/scheduling/provider/OAuth change;
- no Content Asset Library / Drive work;
- no onboarding/auth work;
- no Vercel configuration or deployment.

## Acceptance criteria
1. Operations opens in the shared Kairo product shell and mobile `More` remains selected.
2. The first substantive Operations section is the operator attention queue, not a metric dashboard.
3. Safe retry, manual-review and blocked state remain distinguishable by text as well as semantic colour.
4. Safe retry eligibility remains `retryDisposition === safe && attempt < maxAttempts`.
5. Budgets, automation controls and intervention history remain reachable through keyboard-operable native disclosures.
6. Existing disable forms retain explicit reason input and existing server actions.
7. More groups secondary routes without expanding the five-item mobile primary navigation.
8. More does not falsely imply Settings exists.
9. Desktop/tablet/mobile progressively collapse without horizontal page scrolling.
10. Product Intake, Security baseline, CI and implementation-level UI Review pass on one frozen exact candidate before certification/merge approval.
