# VS-80 — Visual Navigation and Accessibility

## Status
Approved for runtime implementation by Sazid Khan on 2026-08-22 as Batch 7.

## Outcome
Kairo becomes easier to recognize, navigate and operate through a cohesive logo, icon navigation, rapid Brand switching, accessible themes, purposeful motion and clearer interaction states without removing or restructuring existing features.

## In scope — Batch 7 tasks 61–70
1. Add a reusable Kairo logo and compact brandmark across the app shell, onboarding and key empty states.
2. Add one consistent outline icon family to primary navigation and relevant Instagram/Facebook surfaces.
3. Add an accessible Brand switcher with Brand identity, connection context, recent Brands and pinned/favourite Brands where data permits.
4. Add collapsible desktop navigation with labels/tooltips and responsive mobile navigation.
5. Add breadcrumbs and visible Brand/workflow context on primary product screens.
6. Implement light, dark and system theme modes with persistent selection and accessible theme-safe tokens.
7. Standardize primary, secondary, tertiary, success and destructive actions plus links, status chips and connection-health indicators.
8. Add purposeful 100–250ms interaction feedback, loading/success transitions and automatic `prefers-reduced-motion` handling.
9. Improve typography, spacing, focus visibility, keyboard navigation, touch targets, empty/loading/error states and mobile sticky actions.
10. Add deterministic accessibility, theme, navigation and responsive regression coverage.

## Acceptance criteria
- [x] Existing routes and capabilities remain available.
- [x] Logo and icons use reusable, accessible components and one coherent visual family.
- [x] Users can distinguish the current Brand and switch Brands efficiently.
- [x] Navigation remains understandable when expanded, collapsed and on mobile.
- [x] Light, dark and system themes persist and maintain readable contrast.
- [x] Buttons, links, status and channel identity are visually unambiguous.
- [x] Motion is purposeful, brief and automatically respects system reduced-motion preference.
- [x] Keyboard focus, labels and touch targets remain visible and operable.
- [x] Responsive layouts avoid horizontal page scrolling and preserve task hierarchy.
- [x] Runtime, build, accessibility-oriented tests and governance checks pass before merge approval.
