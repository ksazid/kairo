# VS-06 — Critic, Judge and Approval

Status: Proposed for scope approval

## Goal
Separate drafting from independent quality review and make human approval of a specific Content Version enforceable.

## Requirement IDs
- FR-12
- FR-13

## User-visible outcome
Content can move Draft → Review → Approved only after hard truth/policy checks and independent Critic/Judge evaluation, with bounded revisions and explicit human approval.

## In scope
- Drafter/Critic/Judge logical separation.
- Deterministic Truth/Claims Gate and first-person claim policy.
- Bounded revision loops.
- Approval record bound to Content Version, destination context and time.
- Draft/Review/Approved/Archived state controls.
- Critic findings and approval UI.

## Non-goals
- Autonomous publishing.
- Paid advertising.
- Critic override of hard policy.
- Unbounded self-revision loops.

## Dependencies and gates
- VS-05 Content Version model is required.
- Executable external Skills must pass sandbox/provenance controls.
- High-risk security review required before certification.

## Acceptance criteria
1. Hard unsupported-claim or fabricated-experience failures cannot be offset by aggregate quality scores.
2. Critic does not depend on hidden Drafter reasoning.
3. Revision loops are bounded.
4. Approval applies to a specific immutable version.
5. Editing an approved version invalidates/requires new approval as defined by the TRD.
6. Human approval remains mandatory before any external publication path.

## Governance
- Lifecycle: proposed.
- Implementation mode: specification-only.
- Scope, policy and implementation approvals remain pending.
- `.github/workflows/release.yml` remains protected.
- Superpowers begins only after the slice is approved/activated with runtime implementation permission.
