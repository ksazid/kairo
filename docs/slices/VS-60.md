# VS-60 — Google Drive Content Asset Connector

## User job
Let a Brand deliberately connect a Google Drive source to a Content Asset Library and index reusable file metadata without granting Kairo broad access to the user's Drive.

## Scope
- Google OAuth web-server flow for Content Asset Libraries using `https://www.googleapis.com/auth/drive.file` only.
- Short-lived one-time OAuth intents with cryptographically random state; persist only the state hash.
- Encrypted refresh-token storage scoped to Workspace + Brand + provider connection.
- Provider connection status and granted-scope metadata.
- A library can attach one explicitly selected Google Drive root at a time.
- Server-issued short-lived Drive access token endpoint for the authenticated Brand/library so the web UI can launch Google Picker after connection.
- Authenticated root-selection endpoint that verifies the selected Drive item before attaching it to the library.
- Bounded, metadata-only Drive indexing using the selected root and the VS-59 connector boundary.
- Explicit `needs-attention` behavior for expired/revoked credentials, inaccessible roots, partial/incomplete provider results, or traversal limits.
- Disconnect revokes Kairo's local refresh-token credential and clears indexed metadata/root linkage.

## Least-privilege decision
VS-60 requests only `drive.file`. It does not request `drive`, `drive.readonly`, or `drive.metadata.readonly`. Google Picker is the user-controlled authorization surface for selecting Drive content. The implementation must not assume that selecting a folder automatically grants access to every pre-existing descendant; only files/folders the Drive API can actually enumerate are indexed.

## Trust and privacy boundary
- Provider credentials are never returned to the browser.
- The browser may receive a short-lived access token only for the explicitly authenticated Picker flow; the refresh token remains server-side and encrypted.
- Indexing stores metadata/provenance only; no Drive file binary is downloaded or copied into Kairo.
- Content Assets remain production inputs and never create or confirm Brand Brain truth or Knowledge evidence automatically.

## Provider configuration boundary
Code may read optional `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_OAUTH_REDIRECT_URI`, `GOOGLE_DRIVE_PICKER_API_KEY`, and `CONTENT_ASSET_CREDENTIAL_ENCRYPTION_KEY`. VS-60 does not add or change those values in any deployment, Google Cloud project, Vercel, Render, or other provider.

## Acceptance criteria
- Brand and library authorization occurs before every OAuth, token, root-selection, indexing and disconnect operation.
- OAuth state is random, hashed at rest, one-time, short-lived, and account-bound.
- Only `drive.file` is requested and required.
- Refresh tokens are encrypted at rest with authenticated encryption and never logged/returned.
- Provider configuration is optional; Kairo still starts with Google Drive disabled.
- Google Drive HTTP calls have bounded timeouts, response validation and pagination/traversal caps.
- Indexing is metadata-only and preserves provider file references.
- Same external file IDs remain library-scoped through VS-59 asset IDs.
- Provider 401/403/revocation/inaccessible-root outcomes become explicit reconnect/needs-attention states rather than empty-success states.
- Disconnect revokes local credentials and clears root/indexed metadata.
- No Brand Brain mutation occurs.
- Content Assets UI exposes connection state and clear next action without changing primary navigation.
- Product Intake, Security baseline, CI and implementation-level UI Review pass on one exact candidate SHA.

## Non-goals
- Broad Drive scopes.
- Downloading, copying, transforming, OCRing or generating binary assets.
- Google Drive webhooks/watch channels.
- Shared-drive administration or permission changes.
- Automatic Brand Brain ingestion.
- Google Cloud Console/OAuth consent-screen mutation.
- Production secrets, deployment or production enablement.
