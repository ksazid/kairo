# VS-55 — Universal Brand URL Reader

## Requirements

- FR-02 — Brand creation remains extremely lightweight; Kairo may research supplied public sources and propose an initial Brand Brain.
- FR-03 — AI-inferred and owner-confirmed Brand Brain information remain distinguishable and correctable.
- FR-04 — Approved Brand knowledge supports URLs, websites and documents with provenance where available.

## User outcome

A Brand owner keeps the existing lightweight setup flow. Public reference links are optional enrichment. Kairo can read broad public HTTP(S) references including ordinary websites/pages, blogs/articles, public social/profile pages where readable, plain text and text-based PDF URLs. If every supplied reference is unavailable, Kairo can still produce provisional suggestions from owner-confirmed Brand context and the selected objective.

## Scope

1. Preserve SSRF-safe, bounded public URL fetching and redirect revalidation.
2. Improve generic HTML extraction with useful metadata so modern/social pages can contribute when public metadata is returned.
3. Support bounded text extraction from public text-based PDF URLs without claiming success for scanned/encrypted/unreadable PDFs.
4. Treat public source content as untrusted input.
5. Remove the successful-public-reference prerequisite from guided Brand Brain generation.
6. Permit owner-context-only proposals to carry no external source IDs; proposals that cite external sources must still cite only inspected sources.
7. Keep URLs optional in the existing quick setup UI and keep generated fields reviewable/inferred until the owner confirms them.

## Non-goals

- No new onboarding step or source-classification workflow.
- No Google Drive or Content Asset Library connection; that remains separate future scope.
- No browser automation or JavaScript execution for page rendering.
- No bypass of login walls, CAPTCHAs, paywalls, robots/provider restrictions or anti-bot controls.
- No Meta/Instagram OAuth or Graph API change.
- No database migration.
- No publishing, scheduling or approval change.
- No deployment or production enablement in this slice.

## Security constraints

- Only credential-free HTTP(S) URLs.
- Reject local, private, loopback, link-local and other unsafe network targets before transport.
- Re-resolve and revalidate every redirect target.
- Keep response-size, redirect and timeout bounds.
- Never execute retrieved HTML, JavaScript, PDF actions or embedded instructions.
- External text remains untrusted source material and cannot alter Kairo policy, tools, Brand scope or permissions.

## Acceptance criteria

- A normal HTML page yields useful title/summary/body evidence.
- Social/profile-style HTML with OpenGraph/Twitter metadata can yield usable evidence even when little body text is present.
- Plain-text URLs remain supported.
- A bounded text-based PDF URL yields extracted text and is tracked as document evidence.
- A PDF with no safely extractable text fails explicitly and does not fabricate evidence.
- Existing SSRF and redirect protections remain green.
- One failed URL does not prevent use of other successfully read references.
- Zero successfully read URLs does not prevent model generation when a Brand Brain generator exists.
- Owner-context-only proposals are stored as inferred and use empty external source provenance rather than fabricated source IDs.
- If the model runtime itself is unavailable/fails, the API still reports generation unavailable truthfully.
- Quick setup does not require a URL.
- No OAuth/provider, migration or publishing behavior changes.
