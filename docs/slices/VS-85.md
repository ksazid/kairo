# VS-85 — Simplified Home Intelligence and Creation

## Status
Scope and implementation direction approved by the Product Owner on 2026-08-23. Runtime implementation is authorised. Certification, merge, release and production enablement remain separate exact-SHA gates.

## Outcome
Replace the legacy goal-first Home with the approved Kairo Home that answers three questions quickly:

1. What needs me?
2. What can I create?
3. What is Kairo doing next?

The primary Home experience is intentionally simple and action-first while existing Research, Campaign, Critic, rendering, evidence and provider workflow remain underneath.

## Approved Home structure

```text
Needs Attention
My Idea
For You
Up Next
What's Working
Continue
```

Empty or non-useful sections may disappear. Each section must remain visually distinct rather than becoming one wall of identical cards.

## Product rules

- Primary outcomes remain within four clicks where Kairo can safely do the rest.
- One recommended path/action appears first; alternatives are secondary.
- Technical workflow terminology stays out of the default Home experience.
- Kairo may say there is no strong recommendation rather than manufacture filler.
- Existing Brand isolation, evidence, approval and publishing safeguards remain unchanged.

## In scope

### Needs Attention
1. Show only items where Kairo cannot safely continue without user action.
2. Keep `Connect a channel` for Brands without an authenticated publishing destination.
3. Prefer one dominant item and no more than two secondary items.
4. Use plain actions such as `Fix`, `Review` or `Retry`.
5. Hide the section when there is nothing useful to act on.

### My Idea
6. Put user-led creation directly on Home; Creation is not a separate primary destination.
7. Accept a plain-language idea or request and a public link in the first runtime increment.
8. Present Photo, Video and Media affordances only when the underlying attachment/selection path is real; do not fake upload capability.
9. Infer the immediate creation goal from the user's input rather than require a goal questionnaire.
10. Analyse the input before generation and show one recommended format with a concise reason.
11. Permit an explicit format override before starting the existing creation pipeline.
12. Start creation only after the user chooses `Create <format>`.
13. Preserve the existing Idea → Research → Angle → Campaign lineage under the hood.

### For You
14. Rank current eligible Brand Opportunities and show one dominant top pick plus up to three compact alternatives.
15. Explain the top pick in plain language and show its recommended format where reliable data is available.
16. `Use idea` remains the obvious primary action; deeper discovery remains secondary.
17. Never invent filler when no strong Opportunity exists.

### Up Next
18. Build the section from existing Calendar/publishing state.
19. Show one dominant upcoming item plus up to two compact items.
20. Show only plain user-facing states such as Scheduled, Ready, Published or Needs attention.
21. Expose Preview, Reschedule or Fix only where an action is genuinely available.

### What's Working
22. Use existing Brand performance and accepted learning data.
23. Show a small KPI summary where meaningful observations exist.
24. Pair metrics with one concise `What Kairo learned` interpretation when supported.
25. Provide `Create similar` as the preferred action when a supported learning can guide another creation; `View Results` remains secondary.

### Continue
26. Use existing Ideas/Campaigns to surface the most relevant unfinished work.
27. Show one dominant item plus up to two compact recent items.
28. Use context-aware actions such as Continue or View.
29. Full history remains in Content rather than Home.

### Smart Item interaction grammar
30. Reuse Spotlight, Standard and Compact variants with the same interaction grammar: title, one-line context, useful status/type, one obvious action, optional secondary menu.
31. Keep metadata to the minimum necessary for the decision.
32. Technical IDs, versions, provider details and internal processing stages are not default Home content.

### Design and motion
33. Keep the approved Kairo design baseline: light surfaces, restrained accent, clear hierarchy, generous whitespace and modest borders/radii.
34. Apply UI UX Pro Max for flow/responsive/accessibility, Design Taste/Impeccable for hierarchy/polish, Emil principles for purposeful motion, Ponytail for frontend implementation quality, and UI Review as the quality gate.
35. Motion is feedback, not decoration: short entrances, press feedback and state transitions normally under ~300ms.
36. `prefers-reduced-motion` must preserve understandable state changes without movement.
37. No AI glow, confetti, decorative loops or animated primary navigation.

## My Idea recommendation boundary
The current simple-creation pipeline immediately takes a user-selected goal and proceeds through research/angle/campaign construction. VS-85 must not pretend that satisfies the approved `input → analyse → recommended format → create` interaction.

The implementation therefore adds a lightweight, side-effect-free recommendation step before `simple-creations` is started. It may use input characteristics plus existing Brand learning/performance context to infer:

- immediate goal;
- recommended format;
- concise reason;
- supported override choices.

Only after confirmation does the existing durable creation pipeline run. No new onboarding, Campaign or Brand-memory source of truth is introduced.

## Existing safeguards preserved
- Human approval remains required before external publication.
- Brand/workspace tenant isolation remains mandatory.
- Public URLs do not grant provider authority.
- Owner-confirmed Brand facts remain authoritative.
- Weak/unsupported performance inference must not be presented as causal truth.
- Research and evidence lineage remain inspectable contextually.

- [ ] Home renders the approved six-section structure where data exists.
- [ ] Needs Attention preserves post-onboarding channel connection behavior.
- [ ] My Idea no longer requires the user to choose a goal first.
- [ ] My Idea produces a format recommendation before durable creation starts.
- [ ] User can override the recommended supported format before creation.
- [ ] Starting My Idea still creates the existing governed Idea/Research/Angle/Campaign lineage.
- [ ] For You shows one top pick and no more than three compact alternatives.
- [ ] For You suppresses filler when no strong Opportunity exists.
- [ ] Up Next is populated from existing Calendar/publishing state without provider jargon.
- [ ] What's Working uses actual performance/learning data and does not fabricate metrics.
- [ ] Continue uses existing unfinished Brand work.
- [ ] Home remains usable when any non-critical secondary data source fails.
- [ ] Home has one obvious primary action per surfaced item.
- [ ] Desktop and mobile widths remain usable without horizontal scrolling.
- [ ] Keyboard, screen-reader labels, focus behavior and reduced-motion support pass UI Review.
- [ ] Runtime/typecheck/tests/build, security baseline, governance validation and preflight pass before certification.
