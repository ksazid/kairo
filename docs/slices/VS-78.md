# VS-78 — Instagram Performance Learning & Meta MCP

## Status
Approved for runtime implementation by Sazid Khan on 2026-08-22 as Batch 5 of the approved Instagram completion work.

## Requirements
- FR-09 — Angle development
- FR-15 — Publishing
- FR-16 — Performance intelligence

## Outcome
Kairo collects verified Instagram performance after publication, keeps availability and freshness explicit, proposes cautious Brand-scoped Learnings for human acceptance, uses accepted evidence to improve the next recommendation, and exposes replaceable Meta MCP tools over clean publishing and insights abstractions.

## In scope — Batch 5 tasks 41–50
1. Enqueue Instagram Insights collection from verified published posts.
2. Run a bounded durable Insights collection worker with retry and terminal availability states.
3. Normalize reach, impressions, likes, comments, saves, shares and Reel views without treating unavailable values as zero.
4. Persist provider request lineage, capture time, freshness and permission/eligibility failures.
5. Add post-level and Brand-level performance reads with connection health and stale-data semantics.
6. Propose evidence-bound Candidate Learnings from comparable Brand-scoped Instagram observations.
7. Preserve explicit human accept/reject/correct authority before any Learning affects recommendations.
8. Feed accepted Learnings into the next Angle/content-type recommendation with a concise evidence reason.
9. Add a replaceable `InstagramPublisher` and Instagram Insights abstraction beneath Meta MCP.
10. Expose `publish_reel`, `publish_carousel`, `publish_image`, `get_publish_status`, and `get_instagram_insights` MCP tools with tenant and approval enforcement.

## Acceptance criteria
- [x] Every eligible Instagram publication creates one idempotent Insights job.
- [x] Collection retries are bounded and credentials never enter stored observations or responses.
- [x] Missing permissions, ineligible metrics and stale observations remain distinct from measured zero.
- [x] The seven approved Instagram metrics retain provider lineage and capture timestamps.
- [x] Candidate Learnings cite only comparable observations from the same Brand.
- [x] Only accepted Learnings influence a later recommendation.
- [x] Recommendation reasons disclose which accepted Learning influenced ranking.
- [x] MCP handlers authorize Brand/account scope and publish only approved immutable assets.
- [x] MCP tool handlers depend on replaceable publisher/insights ports rather than Meta HTTP.
- [x] Full runtime, migration and governance verification pass before merge approval.
