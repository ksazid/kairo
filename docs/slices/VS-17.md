# VS-17 — Instagram Connection + Insights

Status: Approved and active — runtime implementation authorized outside production

## Goal

Close Kairo's Instagram intelligence loop by allowing an authorised Brand owner to connect an Instagram Professional account through Meta OAuth, use that connection for Kairo's existing deterministic Instagram publisher, and ingest provider-backed media Insights into the existing Performance Memory pipeline.

## Requirements

- FR-05 — Channels
- FR-15 — Publishing
- FR-16 — Performance tracking
- FR-17 — Performance Intelligence
- FR-18 — Brand Learning
- FR-20 — Pilot Operations and Controls

## Authority

- DEC-004 already approves official deterministic Instagram Professional-account adapters, OAuth consent, capability verification and manual fallback.
- The TRD requires OAuth/provider tokens to be encrypted, scoped, revocable and accessible only to deterministic channel adapters.
- No new product-policy decision is required for this bounded implementation.

## In scope

1. Facebook Login for Business connection flow compatible with Kairo's existing `graph.facebook.com` Instagram publisher.
2. One-time, account/Brand-bound OAuth transaction state with expiry and replay protection.
3. Discover Facebook Pages the authorised user can manage and the linked Instagram Professional accounts.
4. Let the user select the intended Page/Instagram Professional account when more than one is available.
5. Persist Brand-scoped connection metadata and an opaque `credentialRef`; never persist a plaintext provider token.
6. Encrypt provider credentials at rest behind a Kairo-owned credential-vault boundary.
7. Connect, disconnect and reconnect-required lifecycle.
8. Preserve the existing publishing `accountRef + credentialRef` seam so approved image/Reel/carousel publishing can use the connected account without exposing credentials.
9. Add a concrete Instagram media-Insights collector behind the existing `MetricCollector` boundary.
10. Normalize only provider-returned metrics supported by Kairo's analytics model; unavailable metrics remain explicitly unavailable.
11. Preserve lineage to the exact Published Post, Campaign, Asset, Version, Brand and external Instagram media ID.
12. Add a compact Brand Performance connection surface showing connection state and allowing connect/disconnect/re-authentication.
13. Safe handling for revoked/expired permissions, provider 401/403, rate limits and transient failures.
14. Webhook-ready connection metadata seam without implementing unrelated engagement automation.
15. Deterministic tests for OAuth state, tenant isolation, credential secrecy, Page/account selection, collector normalization and failure states.

## Out of scope

- Autonomous publishing or removal of human approval
- Instagram consumer/personal accounts
- Stories
- Ads/Marketing API
- DMs, comment automation or OpenReply runtime adoption
- Mixed-media carousel expansion
- Media generation/transcoding
- LinkedIn OAuth changes
- Production Meta credentials, Meta App Review/Advanced Access approval, release, deployment or production enablement

## Acceptance criteria

1. A Brand owner can begin a Meta connection flow without provider credentials entering browser-visible application state.
2. Callback state is single-use, expires, and is bound to the authenticated account and Brand.
3. Only Instagram Professional accounts linked to an authorised Page are eligible for this first connection model.
4. Multiple eligible accounts require explicit selection; Kairo never silently chooses an arbitrary destination.
5. The selected Instagram account ID becomes the publishing `accountRef` and its provider token is reachable only through an opaque `credentialRef`.
6. Plaintext access tokens are not stored in PostgreSQL domain tables, logs, API responses or web state.
7. Disconnect revokes Kairo's local credential availability and prevents future automated dispatch until reconnection.
8. A concrete Instagram collector maps provider media Insights into Kairo's existing raw snapshot + normalized metric model.
9. Provider 401/403 marks the connection/collection path as permission-required rather than inventing metrics.
10. Rate-limit/transient failures retain bounded retry semantics.
11. Cross-Brand access to connection metadata, selection or Insights is rejected.
12. Existing Instagram publishing and manual fallback remain compatible.
13. CI, security baseline, Product Intake, migration verification, governance/preflight and runtime verification pass before exact-SHA certification is requested.
