# VS-71 — Research Start Flow Repair

Status: Active corrective slice

## Goal
Restore the already-approved FR-08/FR-09 user path from a new Idea into evidence-backed Research and candidate Angles so downstream Campaign creation can proceed without test-only seeding or bypassing lineage.

## Requirement IDs
- FR-08
- FR-09
- FR-10 (regression verification only; no Campaign redesign)

## User-visible outcome
On an Idea in `Ready to research`, the user can explicitly start Research. Kairo gathers bounded public evidence, produces a validated Research Dossier and candidate Angles, and returns the user to the same Idea where an Angle can be selected. The existing Campaign flow then becomes reachable.

## Defect being corrected
The certified VS-04 implementation contains Researcher and Strategist orchestration plus PostgreSQL persistence for Research Dossiers and Angles, but the production API/web path never wired an operation that invokes them. The current UI therefore stops at `Evidence gathering has not started.` and tests only pass the boundary by calling the memory repository's `seedReadyBundle` helper.

## In scope
- Add one authenticated Brand-scoped API operation to develop a new Idea into Research + candidate Angles.
- Reuse the existing `ResearcherOrchestrator`, `StrategistOrchestrator`, Research persistence and model-runtime boundaries.
- Wire bounded public research evidence providers already present in Kairo.
- Register the existing Researcher/Strategist output validators with configured Direct/Hermes runtimes.
- Add a clear `Start research` action to the existing Idea detail empty state.
- Add deterministic API tests proving the user-facing path no longer depends on test-only seeding.
- Preserve safe retry/idempotent behavior when Research/Angles already exist.

## Non-goals
- No publishing, approval, scheduling or VS-70 authority change.
- No new social-provider capability.
- No new database migration.
- No autonomous Campaign creation or publishing.
- No redesign of Ideas, Research, Campaigns or Content Studio.
- No relaxation of evidence, Claim, tenant-isolation, prompt-injection or human-control rules.

## Acceptance criteria
1. A Brand member can start Research from a `new` Idea through the product UI.
2. The API preserves Workspace/Brand/Idea scope and safe not-found behavior.
3. Research uses only bounded public evidence and existing Kairo runtime/tool boundaries; provider text remains untrusted input.
4. Persisted Research retains source URLs, dates, Claims, uncertainty and runtime provenance through the existing validators.
5. At least two schema-valid candidate Angles are produced before the flow is considered complete.
6. Repeating the operation after Research + Angles exist returns the existing completed bundle rather than duplicating authoritative state.
7. The existing user can select an Angle and create a Campaign without any seed-only helper.
8. Tests cover start, repeat, unavailable-runtime and tenant-safety behavior.
9. No protected publishing, migration, infrastructure or release paths are modified.

## Governance
- This is a corrective slice for existing approved FR-08/FR-09 behavior, not product-scope expansion.
- The user's explicit `Fix it` instruction on 2026-08-20 authorizes this narrowly described scope and implementation only.
- Policy approval is not required because existing PRD/TRD/VS-04 evidence, provenance, agent and human-control policy remains unchanged.
- Certification, merge, release and production enablement remain separate human gates.
