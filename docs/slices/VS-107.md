# VS-107 — Focused Home Creation Flow

## Status
Implementation expansion approved by the Product Owner on 2026-08-30. The previous visual-only certification is stale; certification, release and production enablement remain pending for the functional candidate.

## Outcome
Make Home the simplest first-value surface: the user chooses a creation direction, Kairo promotes one Brand-fit opportunity, and the existing creation/review path remains available.

## Acceptance criteria
- [x] Home displays a clear creation-intent heading and four format choices.
- [x] Choosing Post updates the URL state and promotes a post opportunity when available.
- [x] Primary recommendation retains the existing Kairo generation action and Brand scoping.
- [x] Existing Home sections and routes remain available.
- [x] Home reads real Brand opportunities, learnings and unfinished work when authenticated.
- [x] Viral-link analysis produces an inline concept preview and passes the source into generation.
- [x] Post, Reel, Carousel and Campaign creation use the existing Brand-scoped simple-creation contract.
- [x] Finished generation opens canonical Content Preview or Campaign Preview.
- [x] Continue Working routes real Campaign and Idea states to their canonical legacy destinations.
- [x] Legacy and v2 applications expose explicit two-way navigation links.
- [x] V2 supports the approved provider-neutral OIDC flow on its own production hostname.
- [x] Production frontend build passes.
- [ ] Browser visual QA passes against the approved Kairo UI direction.
- [ ] Governance validation, preflight and certification pass for the exact candidate SHA.

## Allowed paths
`apps/kairo-ui-v2/**`, `apps/web/app/kairo-product-shell.tsx`, `apps/web/app/shell-baseline.css`, `package-lock.json`, `deployment/dependency-lock.sha256`, `docs/slices/VS-107.md`, `docs/plans/VS-107-implementation.md`, `delivery/**`

## Explicit exclusions
No Hunter algorithm, API, database, identity-provider policy, publishing authority, scheduling, merge, release or production deployment changes. V2 reuses the existing approved OIDC provider and API contracts; it does not introduce a new identity provider or authorization model.
