# VS-99 — Common Source Intelligence Foundation

## Goal

Create one Kairo-owned, provider-neutral source-intelligence boundary shared by Brand onboarding, Research/My Idea and later Hunter enrichment.

```text
public URL
  → SourceRouter
  → selected SourceAdapter
  → NormalizedSourceDocument
  → provenance-aware consumer
```

## Requirements

- FR-02 — Brand creation from one supported public reference
- FR-03 — evidence-backed Brand Brain
- FR-04 — Knowledge and sources with provenance
- FR-06 — Hunter public-source discovery foundation
- FR-08 — Research dossier source evidence
- FR-20 — operational visibility and safe failure

## Acceptance criteria

1. A provider-neutral `SourceAdapter` supports identification, fetching, normalization and health without exposing provider credentials to Brand or agent context.
2. `SourceRouter` deterministically identifies Website, Instagram, Facebook, LinkedIn, YouTube, Substack, RSS/Atom, Hacker News, GitHub, generic article/blog and unsupported URLs.
3. `NormalizedSourceDocument` validates canonical URL, platform/type, useful content/media metadata, content hash, provider/parser version, provenance, confidence and extraction warnings.
4. The existing secure HTTP/PDF reader remains the final generic fallback and retains SSRF, redirect, timeout, response-size and content-type controls.
5. The existing `public-content-fetch` agent capability is implemented through Kairo-owned adapters and rejects forbidden credential/context keys.
6. Fetch routing degrades truthfully when an adapter is unavailable; it must not fabricate content or fail unrelated adapters.
7. Normalized results are idempotently cached by canonical URL, content hash and adapter version without crossing Workspace/Brand boundaries for private evidence.
8. Fetched source material is treated as untrusted data, never instructions.
9. Existing Brand onboarding, Researcher and Hunter behavior remains backward compatible; this slice creates the shared foundation and does not yet add platform-specific deep extraction.
10. No frozen UI, publishing authority, OAuth permission or production scheduling behavior changes.

## Required evidence before certification

- SourceRouter platform matrix tests.
- Normalized document schema/validation tests.
- Website/generic fallback compatibility tests.
- `public-content-fetch` ToolGateway tests including scope and credential rejection.
- Cache hit, miss, unchanged-content and adapter-version invalidation tests.
- SSRF, redirect, huge response, malformed content and prompt-injection-as-data tests.
- Workspace/Brand isolation tests for scoped cache entries.
- Full typecheck, unit tests, build, governance validation and preflight.

## Explicitly deferred

- Deep Website crawling and same-domain sampling.
- GitHub, HN, RSS/Substack, YouTube and social extraction implementations beyond routing boundaries.
- Video transcript, keyframe and OCR processing.
- Brand Intelligence Profile V2 / Topic Graph.
- Hunter query, ranking, durable-run and scheduler changes.
- Any visible scheduled Hunter production enablement.

## Release boundary

Implementation approval does not authorize certification, merge, release, production enablement or deployment. Those remain separate exact-SHA gates.
