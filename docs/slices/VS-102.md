# VS-102 — Media Intelligence and Onboarding Sampling

## Goal

Add a provider-neutral MediaAnalyzer to the shared Source Intelligence pipeline and expand onboarding evidence sampling without creating a second scraping/media stack.

## Acceptance criteria

1. Normalized source evidence can be analyzed for thesis, hooks, claims, facts, entities, visual style, format, presenter cues, CTA and audience cues.
2. Analysis prefers existing captions/transcript evidence, then may use bounded audio→STT, representative-frame extraction and OCR through explicit ports when configured.
3. Media analysis is provider-neutral and does not expose provider credentials to agents or normalized evidence.
4. Unavailable media capabilities degrade independently and add explicit warnings rather than fabricating evidence or failing the entire source read.
5. Media-derived output retains canonical source URL, content hash, provenance, confidence and source-evidence references.
6. Analysis is bounded by deterministic limits for transcript length, frame count, OCR text and processing timeout/budget.
7. Onboarding sampling supports the initial URL plus bounded profile/site context, up to 20 recent items, up to 5 deeper items, and About/Product context where adapters expose them.
8. Sampling is configurable and deduplicated by canonical URL/content hash.
9. Brand onboarding and My Idea continue to reuse the same SourceRouter/MediaAnalyzer pipeline.
10. No frozen UI, publishing authority, OAuth scope, scheduler or autonomous publication behavior changes.
11. Tests cover captions-first analysis, transcript fallback, STT/keyframe/OCR degradation, bounded sampling, deduplication, provenance and no-fabrication behavior.

## Required evidence

- Focused MediaAnalyzer unit tests with deterministic fake ports.
- Sampling/deduplication tests.
- Source Intelligence integration tests.
- Repository typecheck, test, build, governance validation and preflight before certification.

## Release boundary

The Product Owner instruction to proceed authorizes VS-102 scope and implementation only. Certification, merge, release and production enablement remain separate exact-SHA gates.
