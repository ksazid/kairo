# VS-58 — Onboarding + Kairo-owned Auth/Recovery + Final UI Consistency

## Requirement traceability
- FR-01 — Account and Workspace
- FR-02 — Brand creation
- UI-07 from issue #94

## User job
Enter Kairo, add the first Brand with minimal friction, and recover cleanly from Kairo-owned authentication failures without exposing Auth0 credential UX inside Kairo.

## Scope
- Keep first-run onboarding to two conceptual steps: Brand basics, then Brand Brain suggestions/review.
- Preserve the current Workspace + Brand creation server action and redirect contract.
- Keep one optional public Brand reference URL; do not add source classification or a multi-step wizard.
- Explain that website/social/blog/public PDF URLs are optional and that setup continues if a public source cannot be read.
- Remediate Kairo-owned `/sign-in` normal and recovery states to the approved calm/light-first design baseline.
- Never echo arbitrary `error` query text; map known Kairo auth failures to bounded recovery copy and fall back to a generic message.
- Preserve local-only `returnTo` handling.
- Retain visible keyboard focus, semantic headings, labels/help text, touch targets and reduced-motion behavior.
- Complete the UI-07 implementation-level cross-app consistency audit; do not broaden into unrelated runtime surfaces.

## Non-goals
- No redesign or mutation of Auth0 Universal Login.
- No OIDC/Auth0 provider, callback, scope, secret or tenant change.
- No change to `createWorkspaceAction`, account authorization or Workspace/Brand persistence.
- No API/domain/contracts/database/migration change.
- No Content Asset Library / Drive work.
- No new settings/account-preferences implementation.
- No Vercel configuration change, deployment, release or production enablement.

## Responsive behavior
- Desktop/tablet: one centered, quiet first-run/recovery surface with restrained width and whitespace.
- Mobile: single-column flow, reduced outer padding, no shadow dependency, 48px primary controls.
- No horizontal scrolling or alternate mobile information architecture.

## Accessibility states
- Important fields keep visible labels; optional/help text supplements rather than replaces labels.
- Recovery errors use `role="alert"` and textual meaning.
- Sign-in and onboarding primary actions remain keyboard reachable with visible focus.
- No color-only status meaning.

## Acceptance
- Onboarding clearly reads as Step 1 of 2 and points directly to Brand Brain review as Step 2.
- No extra onboarding wizard/classification step is added.
- Arbitrary auth error text cannot be reflected into the Kairo recovery page.
- Safe local return paths are preserved; protocol-relative/external targets fall back to `/`.
- Decorative auth gradients are removed.
- Production build, deterministic tests, Product Intake, Security and CI pass on one frozen exact candidate SHA.
- Implementation-level UI Review PASS before certification.
- Merge and Vercel deployment remain separate owner approvals.
