# VS-87 — Content Library and Canonical Preview

## Goal

Make `Content` the user-facing working surface for generated Brand content without exposing Campaign, Research, Critic, renderer or publishing implementation machinery as primary navigation.

## Requirements

- FR-10 Campaign lineage remains retained internally.
- FR-11 Content Studio becomes a quiet content-first Content Detail / Preview experience.
- FR-12 Drafter/Critic/Judge remain progressively disclosed; no permanent agent workflow chrome.
- FR-13 human approval remains mandatory and binds the exact immutable version/destination.
- FR-14 Schedule for later remains secondary on the same Preview surface.
- FR-15 Publish now remains the primary post-approval action and must not claim Published before provider settlement.

## Approved user flow

`Content` → filter/list Smart Item → Content Detail / Preview → Improve/Edit if needed → `Approve & Lock` → `Publish now` or `Schedule for later`.

## Content library

- Route: `/brands/:brandId/content`.
- User-facing filters: `All`, `Needs you`, `Ready`, `Scheduled`, `Published`.
- Single-column list; no Campaign dashboard, KPI wall or card grid.
- Each row shows useful title, channel/format, concise status and one state-aware primary action.
- Internal Campaign ID/lineage may remain in URLs/data but is not primary copy.
- Empty state points creation back to Home/My Idea rather than introducing a separate top-level creation workflow.

## Content Detail / Preview

- Existing Campaign/asset contracts are reused; the normal Content entry filters the working surface to the selected asset.
- Generated channel executions form preview tabs. Only channels/formats actually present for the content appear.
- Single-channel content renders one channel tab.
- Text/image content shows the exact current immutable Content Version copy in Preview.
- Carousel and Reel media reuse the existing exact-render review/editor surfaces; Content links into those surfaces without duplicating renderer state.
- Evidence, version history, production assets, AI transformations and Critic findings stay progressively disclosed.
- `Approve & Lock` is the dominant approval action after review passes.
- Editing after approval creates a new version and therefore requires fresh review/approval.

## Presenter

The approved Presenter selector is conditional. VS-87 must not fabricate Avatar state before Brand Avatar support exists. With no eligible Brand Avatar capability in the current product, the selector remains hidden. UI-05 will provide the configuration dependency.

## Publishing

- Reuse current destination-specific approval and connected Channel Account contracts.
- `Publish now` is primary after approval.
- `Schedule for later` is secondary/progressive disclosure.
- Queued/processing status remains truthful until provider settlement.
- No new worker, Meta/provider, idempotency or scheduling policy is introduced.

## Responsive/accessibility

- Desktop: calm single-column content list with compact filters; Detail may use one primary content column plus progressive disclosures.
- Mobile: single-column list, touch-safe filter controls, same five-destination shell.
- All filters/actions keyboard operable and screen-reader labelled.
- State is communicated with text, not colour alone.

## Explicit exclusions

- No new database/migration.
- No API/worker/provider changes.
- No autonomous publishing.
- No Avatar implementation.
- No Calendar/Insights redesign.
- No production deployment.

## Acceptance

1. Primary nav Content opens `/brands/:brandId/content`.
2. Content library exposes only approved filters and state-aware actions.
3. Campaign terminology is no longer the primary Content landing experience.
4. Selecting a content item opens the correct exact-version asset workspace.
5. Channel tabs contain only existing channel executions.
6. Review/approval is still exact-version bound and the dominant approval label is `Approve & Lock`.
7. Publish now remains primary and Schedule for later secondary after approval.
8. Existing carousel/video exact-render paths remain reachable from Content and use Content navigation language.
9. No presenter control appears when no eligible Avatar exists.
10. Typecheck, tests, build, preflight and governance validation pass before certification request.
