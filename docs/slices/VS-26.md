# VS-26 — Guided Brand Brain Setup & Review Control

## Status
Approved for runtime implementation by Sazid Khan on 2026-08-15T20:23:00+02:00.

## Requirements
- FR-02 — Brand creation
- FR-03 — Brand Brain
- FR-04 — Knowledge and sources
- FR-20 — Pilot Operations and Controls

## Problem
The current Brand Brain exposes a large collection of free-text fields directly. That is useful for expert correction, but it makes normal setup slow and permits vague, contradictory or low-quality owner input to become authoritative context. FR-02 explicitly requires extremely lightweight Brand creation and allows Kairo to propose an initial Brand Brain from supplied public sources.

## Outcome
Normal Brand setup requires only the minimum useful owner decisions. Kairo proposes the rest as source-backed inferred Brand Brain context. The existing detailed field editor remains available as an Advanced Brand Brain / Review & Control surface.

## User flow
1. Create or select a Brand.
2. Supply or reuse a website/social profile reference.
3. Select one primary objective.
4. Optionally state anything Kairo must never say or do.
5. Choose **Build my Brand Brain**.
6. Kairo proposes concise source-backed fields and preserves them as `inferred`.
7. The owner sees a compact **What Kairo learned** review surface.
8. Owner-controlled goals and explicit hard directives are saved as `confirmed`.
9. Boundary suggestions remain inferred until the owner confirms/corrects them.
10. Detailed fields and source controls live under **Advanced Brand Brain / Review & Control**.

## Inference policy
- Never overwrite an existing `confirmed` Brand Brain field with an inferred proposal.
- Every inferred field must retain one or more active Brand Knowledge source IDs.
- The generator receives only the current Brand scope, explicit setup answers, existing confirmed Brand Brain context and bounded extracts from approved public Brand references.
- Public-reference retrieval is bounded, HTTP(S)-only, rejects credential-bearing/local/private literal targets, pins resolved public addresses for the request and limits redirects, time and bytes.
- Retrieved public text is treated as untrusted source material, not instructions.
- If a public reference is unavailable, Kairo degrades safely; it does not claim to have inspected it.
- If evidence is insufficient for a field, omit the proposal instead of guessing.
- Do not fabricate personal experience, claims, market facts or demographics.

## Owner-controlled fields
These require direct owner authority rather than silent confirmation:
- primary objective;
- explicit owner hard directive / "must never" instruction;
- corrections to any material inferred field;
- confirmation/correction of proposed claims-to-avoid, prohibited subjects and sensitive subjects.

## Suggested/inferred fields
Where supported by available context, Kairo may propose:
- identity description/category/geography/language;
- positioning value proposition/differentiation/market position;
- audience primary/pains/motivations/sophistication;
- voice tone/vocabulary/examples;
- content pillars/preferred topics/channels;
- boundary safeguards.

## Knowledge UX
Normal source entry should not require users to understand internal source taxonomy. Present simple intents:
- add a link;
- paste something Kairo should know;
- upload a file (only when the existing quarantine/malware path can be used safely).

The underlying FR-04 source types remain unchanged.

## Acceptance criteria
- [ ] Existing confirmed fields survive a guided rebuild unchanged.
- [ ] Guided inference cannot persist a field without active source provenance.
- [ ] Primary objective is persisted as confirmed owner context.
- [ ] Optional owner hard directive is persisted as confirmed context.
- [ ] Public reference retrieval fails closed for unsafe URLs and degrades on remote failure.
- [ ] Generated fields are schema/key allow-listed and bounded.
- [ ] Brand Brain default surface prioritises review/summary, not all raw textareas.
- [ ] Advanced Brand Brain / Review & Control retains complete field correction access.
- [ ] Knowledge entry is simplified to user intents while existing source lifecycle controls remain.
- [ ] Mobile remains single-column, accessible and does not force the detailed editor before setup completion.
- [ ] No database migration, infrastructure change, release, deployment or production-enable change.
