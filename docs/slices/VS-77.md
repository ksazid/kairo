# VS-77 — Visual Carousel Review & Verified Publishing

## Status
Approved for runtime implementation by Sazid Khan on 2026-08-22 as Batch 4 of the approved Instagram completion work.

## Requirements
- FR-08 — Content development
- FR-11 — Content Studio
- FR-13 — Approval workflow
- FR-15 — Publishing

## Outcome
Kairo persists rendered carousel versions, lets a user visually review and edit individual slides, locks approval to one immutable rendered version, publishes exactly those approved assets through temporary object-storage URLs, and verifies the resulting Meta publication.

## In scope — Batch 4 tasks 31–40
1. Persist CarouselProject, ordered slides and optimistic asset versions against the Content record.
2. Persist rendered carousel and per-slide asset versions with object-storage keys and immutable checksums.
3. Provide temporary public delivery URLs through a replaceable object-storage port for Meta ingestion.
4. Preview every rendered slide with deterministic quality findings and aggregate readiness.
5. Edit slide text or replace a bounded image reference without regenerating the full carousel.
6. Reorder slides and change approved template/style choices with stale-version protection.
7. Queue regeneration of one slide and preserve every prior render version.
8. Approve only a quality-ready rendered version and lock its assets immutably.
9. Extend publish records with media type, Meta container/publish IDs, retries, failure reason, published URL and approved asset version.
10. Verify the lifecycle `Approved → Publishing → Processing → Published / Failed` and persist the actual Meta media result.

## Acceptance criteria
- [x] Review presents actual rendered slide media rather than text alone.
- [x] Every edit creates or advances a version and rejects stale writes.
- [x] Single-slide regeneration preserves other slide versions and prior evidence.
- [x] Reordering and style changes are Brand- and Content-scoped.
- [x] Approval binds one immutable rendered asset version and blocks later mutation.
- [x] Publishing resolves only approved checksummed media through short-lived storage delivery URLs.
- [x] Publish records preserve container ID, media ID, state, attempts, failure and permalink.
- [x] Processing is polled within bounded retry/backoff policy and ends published or failed.
- [x] Unsupported or unready media fails closed without substituting another asset.
- [x] Focused and full runtime verification pass before a draft PR is offered.
