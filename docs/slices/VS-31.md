# VS-31 — Platform-specific Content Adapters

## Goal

Make channel-specific content rules explicit and reusable so Kairo can create one Campaign with channel-appropriate executions without embedding Instagram/LinkedIn behavior in the core content-intelligence prompt.

## Requirements

- FR-05 — Channels
- FR-10 — Campaign
- FR-11 — Content Studio
- FR-12 — Drafter, Critic and Judge
- FR-15 — Publishing

## Scope

1. Add deterministic content-channel profiles for the currently supported LinkedIn, Instagram and manual channels.
2. Profiles expose structured drafting guidance and hard text/caption limits independently of the LLM provider.
3. The Drafter must receive the resolved channel profile with the bounded generation context.
4. Generated text must be validated against the channel profile before a new Content Version can be returned for persistence.
5. Channel adaptation must fail closed; Kairo must not silently truncate generated content to satisfy a platform limit.
6. Existing deterministic publishing adapters should reuse the same content-limit policy where applicable so generation and provider execution do not drift.
7. Existing single-channel and VS-30 multi-channel flows must remain backward compatible.

## Explicit non-goals

- No new social network/provider.
- No Facebook, X, TikTok, YouTube or newsletter implementation in this slice.
- No OAuth or credential changes.
- No production enablement or deployment.
- No real publication.
- No Content Studio redesign.
- No Creative Blueprint/template/video work; those remain later roadmap priorities.
- No autonomous publication.

## Architecture

```text
Campaign / Content Asset
        |
        v
ChannelContentProfileResolver
  | LinkedIn
  | Instagram
  ` Manual
        |
        +--> structured Drafter context
        |
        +--> deterministic output validation
        |
        `--> shared content-limit policy used by publishing adapters
```

The content profile is application-owned deterministic policy. It is not a provider SDK and does not receive credentials. Provider API execution remains in the existing publishing adapters.

## Acceptance criteria

- LinkedIn and Instagram drafts receive different structured profile context.
- LinkedIn generated text over its configured hard limit is rejected before Content Version creation.
- Instagram generated caption text over its configured hard limit is rejected before Content Version creation.
- Manual channel remains a safe generic fallback.
- No adapter silently truncates content.
- Existing provider adapters still reject unsupported content/media/account combinations.
- Deterministic tests cover profile resolution, Drafter context/validation and publishing adapter compatibility.
- Product Intake, Security and CI/preflight/runtime verification pass on the final candidate SHA.

## Safety

Human approval, approved-version enforcement, destination approval, credentials, idempotency and external publication remain owned by existing deterministic publishing controls. This slice changes content adaptation only.
