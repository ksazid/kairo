# VS-34 — App Shell + Today + Discover Design Remediation

## Goal

Bring the authenticated Kairo workspace frame, Today and Discover back to the approved calm, content-first design baseline without changing Opportunity domain semantics, APIs, publishing authority or product policy.

## Requirements

- FR-01 — Account and Workspace
- FR-02 — Brand creation/context
- FR-06 — Hunter / Discover

## User outcome

A user can stay oriented in one stable Kairo workspace, see the selected Brand clearly without it competing with content, and answer “What deserves my attention now?” from an Opportunity-first Today experience. Discover remains a deeper evaluation list rather than a metrics dashboard.

## Scope

- Extract a reusable authenticated product shell for the bounded Today/Discover surfaces.
- Centralize the approved desktop navigation labels and the five-destination mobile navigation model.
- Standardize selected-route state, Workspace/Brand context and sign-out placement for the bounded pages.
- Keep the approved primary navigation model: Today, Discover, Ideas, Campaigns, Content Studio, Calendar, Performance and Brand Brain.
- Keep the approved mobile model: Today, Discover, Ideas, Calendar and More.
- Redesign Today so the ranked Opportunity list is the first meaningful working content after the page heading.
- Keep Today capped at three non-ignored Opportunities.
- Demote Workspace/Brand switching and recommendation-system explanation into secondary/progressively disclosed context.
- Redesign Discover so active Opportunities dominate and aggregate counts read as lightweight context rather than dashboard tiles.
- Preserve Opportunity relevance/evidence/freshness/status, Why now, Develop, Save and Ignore behaviour.
- Improve semantic heading hierarchy, focus visibility, touch reachability and responsive collapse within the changed surfaces.
- Preserve current loading/error/empty/not-found truthfulness and avoid fabricated activity.

## Non-goals

- No Campaign or Content Studio workflow redesign in this slice.
- No Opportunity API/domain/schema changes.
- No new navigation destination or information architecture expansion.
- No dark mode.
- No external visual system replacing Kairo tokens.
- No ornamental AI visuals, gradients, glassmorphism or dense enterprise-dashboard treatment.
- No deployment, production enablement, external publication or autonomous merge.

## Design reads

**App shell** — authenticated product frame; user job: preserve orientation and Brand scope; medium density; Kairo core product family.

**Today** — editorial attention queue; user job: decide what deserves development now; low/medium density; Opportunity-first hierarchy.

**Discover** — opportunity evaluation list; user job: inspect more active Opportunities, understand evidence and act; medium density; list-first rather than dashboard-first.

## Responsive model

- Desktop: persistent sidebar plus one primary content column; Brand scope remains compact and secondary.
- Tablet: retain navigation/context hierarchy while reducing side-by-side secondary content.
- Mobile: single working flow with the five approved bottom destinations; no horizontal page scrolling; primary actions remain reachable and explicit.

## States

- Loading: preserve route loading semantics and avoid layout jumps where already implemented.
- Empty: explicitly state that no strong Opportunity cleared thresholds.
- Partial/error: show safe notices without hiding existing usable Opportunity data.
- Missing Brand: provide a clear return path rather than a blank/null page.
- Success: notices remain polite status messages and do not displace the working hierarchy.

## Acceptance criteria

1. Today and Discover use one shared product shell/navigation implementation instead of page-local duplicated desktop/mobile navigation.
2. Today visually prioritizes the ranked Opportunity list above secondary Workspace/Brand/system explanation.
3. Today still shows at most three strong non-ignored Opportunities.
4. Discover visually prioritizes Opportunity evaluation over aggregate counters.
5. Opportunity relevance, evidence, freshness/status, Why now and Develop/Save/Ignore semantics are unchanged.
6. Brand/Workspace context remains understandable but does not visually compete with page content.
7. Desktop, tablet and mobile preserve the same conceptual hierarchy without page-level horizontal scrolling.
8. Mobile retains exactly five primary destinations: Today, Discover, Ideas, Calendar and More.
9. Semantic headings, keyboard navigation, visible focus, non-colour status communication and touch targets remain accessible.
10. No API/domain/database/publishing/deployment behaviour changes in this slice.
11. UI Review must return PASS before certification.
