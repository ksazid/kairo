# VS-34 — Format Intelligence Library

## Status

Active implementation slice under owner instruction on 2026-08-17.

## Goal

Give Kairo one reusable, explainable source of format intelligence so Angle development and Content Studio can recommend an appropriate content format before approval and publishing without turning recommendations into publication authority.

The library sits above the existing `creative-formats`, marketing-skill and publishing contracts. It does not create a second content-generation or publishing subsystem.

## Product authority

- FR-03 — Brand Brain preferred formats and channels
- FR-09 — Angle development may recommend format/channel
- FR-10 — one Campaign may produce multiple channel executions
- FR-11 — Content Studio stores channel/format metadata and supports human editing
- FR-12 — Critic evaluates structural and channel fit

## Dependencies

- Existing `packages/domain/src/creative-formats.ts`
- Existing `packages/domain/src/skill-registry.ts`
- Existing `packages/domain/src/publishing.ts`
- VS-30 Unified Multi-channel Publishing Gateway
- VS-33 Channel / Account Groups

## In scope

1. Add a typed, deterministic catalog for Kairo content formats.
2. Align strategy formats with the existing publish content types without replacing either contract.
3. Describe best-fit objectives, channel-fit signals, production effort, strengths, trade-offs, composition guidance and review checks.
4. Add deterministic recommendation/ranking from channel, objective and production-effort inputs.
5. Keep recommendation reasons explicit and concise.
6. Keep connected-account capability checks authoritative for actual publishing; format intelligence is advisory.
7. Expose the library as a quiet Brand-scoped product page reachable from the existing More surface.
8. Provide simple URL-state filters for channel, objective and production effort without client-side state machinery.
9. Preserve Kairo's approved light-first, content-first design system and responsive hierarchy.
10. Add deterministic domain tests and formal UI-review evidence.

## Explicit non-goals

- No new provider or social network.
- No OAuth or credential changes.
- No provider API limit scraping or volatile provider policy copied into authoritative domain state.
- No media transformation pipeline.
- No image/video generation or editing.
- No autonomous format selection that bypasses the user.
- No approval, scheduling or publishing authority.
- No database migration or persistent per-Brand format preference in this slice.
- No performance-learning rewrite; accepted Brand Learnings remain a later input to recommendation quality.
- No deployment or production enablement.

## Core invariant

`Format intelligence can recommend what fits; only existing reviewed content, explicit human approval and connected-account capability may authorize publication.`

## Recommendation model

The first library is product-contract intelligence, not a claim about live provider algorithms.

Each profile may express:

- Kairo format key and publish content type;
- corresponding marketing strategy format where one exists;
- channel-fit strength (`primary`, `useful`, `limited`);
- common objectives;
- production effort;
- strengths and trade-offs;
- composition guidance;
- pre-approval review checks.

Ranking is deterministic and explainable. It must not imply that a format will cause superior real-world performance.

## Acceptance criteria

1. Catalog entries have stable unique IDs and validated enums.
2. All five current publish content types (`text`, `image`, `video`, `carousel`, `reel`) are represented.
3. Carousel/Reel profiles reference the existing validated creative-plan contracts rather than duplicating their detailed structure.
4. Recommendations are deterministic for the same inputs.
5. Channel fit, objective fit and production effort influence ranking through transparent rules.
6. Advice never claims a provider capability; actual publishing still checks the destination account's `PublishCapability`.
7. Advice never claims causal performance improvement.
8. The Brand-scoped library page works without JavaScript, uses semantic headings/labels and does not rely on colour alone.
9. Desktop/tablet/mobile layouts reuse existing Kairo components/classes and do not introduce a competing visual system.
10. The page is reachable from More without expanding primary navigation.
11. Domain tests, repository preflight, runtime verification, dashboard build, Product Intake and Security pass before certification.
12. Certification and merge remain an exact-SHA human gate.
