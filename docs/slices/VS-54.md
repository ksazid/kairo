# VS-54 — Video Creation / Editing Tooling

**Status:** approved / implementing  
**Risk:** medium  
**Implementation mode:** runtime-enabled, non-production

## Outcome
Kairo can turn an existing Claim-linked `ReelPlan` into a human-editable Video Project, let the user make bounded timeline/copy edits, and compile the result back into the existing validated Reel/render/publishing path without creating a second media pipeline or weakening exact-version review and approval.

## Governing requirements
- FR-11 — Content Studio
- FR-12 — Drafter, Critic and Judge
- FR-13 — Approval workflow
- FR-15 — Publishing

## Dependencies already delivered
- VS-18 Creative Asset Production — deterministic Reel storyboard + render manifest.
- VS-20 Publishable Creative Media Pipeline — bounded private MP4 encoding and publishing-media egress.
- VS-34 Format Intelligence Library — Reel/video format guidance and explicit reuse of `ReelPlan`.
- VS-52 Campaigns + Content Studio Design Remediation — current calm editor-first product shell.

## In scope
1. Add a typed `VideoProject` contract that is explicitly derived from and compiles back to the existing `ReelPlan` contract.
2. Preserve Workspace, Brand, Campaign, Content Asset and source-version lineage on the editable project.
3. Preserve supporting Claim lineage globally and per scene; a scene cannot introduce a Claim outside the project lineage.
4. Provide deterministic scene-copy editing, scene reordering and scene-duration editing while maintaining a contiguous valid Reel timeline.
5. Provide canonical serialize/parse round-tripping for Video Projects so project state can move through Kairo-owned application boundaries without provider-specific state.
6. Add a bounded Content Studio video-editing experience for Reel/video work that keeps primary creative work central and review/approval secondary.
7. Reuse the existing VS-18 renderer and VS-20 MP4 pipeline for render preparation; do not create a second encoder, object store or publishing path.
8. Any saved edit remains subject to the existing immutable Content Version, Truth/Critic review and destination-specific human approval gates before scheduling/publishing.
9. Deterministic tests cover scope, Claim lineage, timeline continuity, reordering, retiming and serialization integrity.

## Parallel-work isolation
A separate Kairo work thread owns the new **Media Transformation Pipeline**. VS-54 must not implement or modify that capability. In particular, this slice does not own generic resize/crop/transcode/compress/thumbnail/platform-adaptation work.

To prevent cross-chat governance collisions, this branch records its bounded approval/context in `docs/slices/VS-54.md` and `delivery/context/VS-54.md` and intentionally does **not** modify the repository-global `delivery/current-slice.json` while the parallel Media Transformation slice is active. Before certification, the active-slice ledger must be reconciled against latest `main` without overwriting concurrent work.

## Explicit exclusions
- Media Transformation Pipeline implementation or its files.
- Generic image/video resize, crop, transcode, compression, thumbnail or platform-adaptation services.
- New FFmpeg command grammar, encoder or shell execution.
- AI image/video generation.
- Voice synthesis.
- Stock-media search.
- New social provider/OAuth capability.
- Autonomous review, approval, scheduling or publishing.
- New public object-storage exposure.
- Release, deployment or production enablement.

## Acceptance criteria
1. A valid `ReelPlan` can initialize one scoped Video Project and compile back to an equivalent valid `ReelPlan`.
2. Every project carries Workspace/Brand/Campaign/Asset/source-version lineage and rejects missing or malformed scope.
3. Scene edits retain the existing scene identity and reject unsupported Claim IDs.
4. Reordering scenes preserves scene durations and deterministically recalculates a contiguous timeline starting at zero.
5. Retiming a scene deterministically recalculates later scene boundaries and the target duration, remaining inside existing Reel limits.
6. Canonical serialization round-trips without changing the compiled Reel plan.
7. Content Studio exposes Reel/video editing without replacing Kairo's current design system or making AI controls dominant.
8. Rendering/export reuses VS-18/VS-20 contracts; no duplicate media encoder/storage/publishing authority is introduced.
9. Editing content creates/targets a new immutable Content Version and never carries forward approval as authority for the changed version.
10. CI, Product Intake, Security, UI Review where applicable, repository preflight and runtime verification pass on one exact final SHA before certification is requested.
