## Goal

Make Home `My idea` accept real photo/video inputs and reusable existing Brand media, store new media privately through the existing S3-compatible object-storage boundary (Cloudflare R2 in production), and expose the already-governed optional Brand Presenter only when it is genuinely eligible. Preserve the frozen Kairo Home visual DNA and keep AI generation as one clear primary action.

## In scope

1. Reuse the existing private S3-compatible storage configuration for Kairo-managed Home media; do not introduce another storage vendor or browser-visible credential.
2. Add Brand-scoped direct-upload signing so the browser uploads photo/video bytes directly to private object storage using a short-lived presigned PUT.
3. Keep object keys opaque and Brand-scoped; do not expose raw Workspace/Brand identifiers in object-key paths.
4. Persist upload intent/completion server-side and index completed files into the existing Brand Content Asset Library using the `manual` provider as the Kairo-managed media library.
5. Make `Photo` and `Video` Home controls operational. Successful uploads are automatically reusable later through `Media` without copying bytes again.
6. Make `Media` open a compact accessible picker for previously uploaded Brand image/video assets and allow multiple selection.
7. Persist selected media asset IDs on the durable simple-creation request with Workspace/Brand authorization. Do not treat user-supplied IDs or object keys as trusted.
8. Preserve selected media references through the creation view so downstream Content/Preview work can retain exact lineage. This slice does not claim multimodal model understanding where no governed binary-understanding adapter exists.
9. Fetch the Brand Presenter eligibility projection on Home. Show a Presenter selector only when `eligibility.status === "eligible"`; `None` remains the first/default option and the server repeats eligibility validation.
10. Place the Presenter control contextually after Format and before generation, not as permanent shell/navigation chrome.
11. Replace the post-recommendation `Create <format>` action with `AI Generate` and reuse the same `sparkles` Kairo AI icon used by `Get recommendations`.
12. Preserve the current `For you` card geometry. Selecting a recommendation continues to seed `My idea`; Presenter/media/generation controls live in the creation boundary instead of expanding every recommendation card.
13. Preserve loading, upload progress, completion, error, retry/removal, empty-library and provider-unavailable states truthfully.
14. Preserve mobile/desktop hierarchy, keyboard access, visible focus, reduced-motion behavior, and no horizontal page overflow.

## Storage contract

```text
Browser
  -> Kairo API authorizes Brand + validates metadata
  -> short-lived presigned PUT
  -> private S3-compatible object storage (Cloudflare R2 in production)
  -> Kairo API verifies upload completion
  -> existing Content Asset Library metadata in PostgreSQL
  -> Home Media picker / simple_creation_requests media references
```

R2 remains private. PostgreSQL stores metadata and lineage; it does not store image/video bytes. Signed delivery URLs are temporary and are never persisted as durable media identity.

## Presenter contract

```text
Brand Presenter profile
  + verified AvatarProvider capability
  -> PresenterEligibility
  -> Home selector only when eligible
  -> None default or explicit presenterId
  -> server revalidation
  -> durable simple creation
```

No fake Presenter, provider readiness or avatar execution is introduced.

## Design lock

This is a functionality wiring slice, not a Home redesign.

- Keep the frozen Home order and shell unchanged.
- Keep current Kairo tokens, typography, radii and spacing.
- Keep purple primary emphasis scarce.
- Do not add gradients, glow, glassmorphism, oversized AI decoration, new navigation, or a permanent media side panel.
- `Get recommendations` and `AI Generate` are the only AI-forward primary actions in this local flow and both use the existing `sparkles` icon.
- Attachments and Presenter are compact contextual controls using progressive disclosure.

## Explicit non-goals

- No new primary navigation destination.
- No replacement of the Content Asset Library architecture.
- No public R2 bucket or permanent public asset URLs.
- No storage credentials in web/client code.
- No face/voice cloning or biometric enrollment.
- No automatic Presenter selection.
- No claim that the generation model visually understands an uploaded photo/video until a governed multimodal adapter is implemented.
- No avatar/video provider execution or Test Clip implementation.
- No autonomous publishing or approval-policy change.
- No implementation of unrelated Home gaps FG-HOME-004 through FG-HOME-007.
- No merge, release or production deployment without later exact-SHA approvals.

## Acceptance criteria

- [ ] Photo accepts supported image files, authorizes Brand scope, uploads to private configured storage and returns a reusable media asset.
- [ ] Video accepts supported video files through the same private path.
- [ ] Upload credentials never reach the browser; only a short-lived scoped presigned URL does.
- [ ] Incomplete/expired upload completion fails closed.
- [ ] Completed Photo/Video assets appear under `Media` without another upload/copy.
- [ ] Media picker supports image/video filtering/selection and a truthful empty state.
- [ ] Cross-Brand media IDs are rejected before simple creation persistence.
- [ ] A creation may persist zero or bounded multiple media asset IDs and returns them in the creation view.
- [ ] Existing text/URL-only creation behaves unchanged.
- [ ] Presenter selector is absent when no eligible Presenter exists.
- [ ] When eligible, Presenter appears after Format with `None` first/default.
- [ ] Forged, disabled, cross-Brand or provider-unavailable Presenter IDs still fail closed server-side.
- [ ] Final generation action reads `AI Generate` and uses `<KairoIcon name="sparkles" />`, matching `Get recommendations` iconography.
- [ ] `For you` cards retain frozen geometry; selecting an idea routes into the same My Idea creation boundary.
- [ ] No shell/navigation or approved Home hierarchy change.
- [ ] Relevant API/web tests, clean migrations, typecheck/build, UI Review, responsive checks, accessibility checks, Security, Product Intake and repository preflight pass on one immutable candidate before certification is requested.

## Production dependency

Direct browser upload requires the existing private R2 bucket CORS policy to allow the Kairo production/preview web origins for `PUT` with the signed `Content-Type` header. Code must fail truthfully if that external configuration is missing; this slice does not silently make the bucket public.
