# VS-73 — End-to-End Production Reliability Repair

## Goal
Close the production-observed reliability gaps across the authenticated multi-Brand Idea → Research → Angles path without weakening tenant isolation, authentication, research relevance controls, or publishing authority.

## In scope
- Bounded retry/backoff for model and research providers on 429 and transient upstream failures, honoring `Retry-After` within a bounded delay.
- Retry-safe Idea development: if Research persisted but Strategist failed, the next development command resumes at Strategist and does not repeat Research.
- FR-02 creation of additional Brands inside an existing authenticated Workspace.
- Safe-not-found tenant isolation for cross-account Workspace/Brand operations, including Brand creation and Research development.
- Authenticated multi-Brand smoke architecture using a bearer token; no auth bypasses.
- Explicit web/API Git SHA provenance and smoke verification against an expected exact SHA.
- Regression coverage through Brand → Idea → Research → Angles → Campaign/content gates where deterministic stores permit it.

## Out of scope
- New research providers or crawlers.
- Database schema migrations.
- Authentication relaxation or test-only production bypasses.
- Autonomous external publishing or creating a real LinkedIn/Instagram post in smoke tests.
- Changes to publishing authority or protected publishing execution paths.

## Acceptance criteria
1. A 429 or retryable 5xx from an LLM provider is retried a bounded number of times; `Retry-After` is honored subject to the configured cap; non-retryable 4xx responses are not retried.
2. OpenAlex/Crossref transient rate limits receive the same bounded retry treatment while preserving the existing public-only and relevance boundaries.
3. If Research exists and fewer than two candidate Angles exist, the product presents a recover/continue action and the API resumes Angle generation without rerunning Research.
4. An authenticated member of a Workspace can create an additional Brand there; a foreign account receives safe not-found behavior and cannot create or enumerate Brands in that Workspace.
5. Multi-Brand tests prove Brand A and Brand B remain scoped and foreign accounts cannot access either by identifier.
6. Production smoke accepts an auth token, exercises two Brand scopes without publishing externally, and validates the expected exact Git SHA.
7. The web application exposes its deployment Git SHA and the API `/version` endpoint continues to expose the runtime release SHA.
8. CI, Security and Product Intake pass on the final exact candidate SHA; release/production verification is performed against the exact deployed SHA.
