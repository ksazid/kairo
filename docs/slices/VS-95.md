# VS-95 — Approved Brand, Avatar and Provider Interaction Wiring

## Status

- Lifecycle: implementing
- Risk: low
- Implementation mode: runtime-enabled
- Requirements: FR-03, FR-04, FR-05, FR-11, FR-13
- Product authority: `product/PRD.md`, `product/DESIGN.md`, `product/APPROVED-UI-PAGES-CONTEXT-2026-08-25.md`
- Scope/implementation approval: Product Owner request on 2026-08-25 to implement every approved interaction that is already supported and durably record the interactions that still require product/runtime implementation.
- Certification / release / production enable: not approved by this request.

## Goal

Make the already-approved Brand, Avatar (Presenter), and Settings → AI & Media Providers surfaces behave like real product UI rather than a collection of visual affordances. Reuse existing runtime actions and routes wherever the required capability already exists. Where a capability does not exist, keep the UI truthful and record the exact missing implementation rather than inventing success, credentials, provider health, or media output.

## In scope

### Brand

- Preserve existing local inline Brand-field editing.
- Preserve dedicated Channels and Avatar destinations.
- Wire Instagram Brand-source refresh to the existing governed source-refresh action when an Instagram source account exists.
- Keep Website/source management reachable through the Sources section without fabricating a Website refresh operation that the current API does not expose.

### Avatar (Presenter)

- Preserve `Back to Brand`.
- Add an explicit `Go to Settings` route to the approved AI & Media Providers surface.
- Make Kairo recommendation rows navigate to the corresponding editable presenter preference in the current form: Style, Voice, Language, Framing, Background and Mode.
- Keep `Customize` as a local jump into presenter preferences.
- Preserve the real `Create & Save` server action.
- Show Test clip truthfully as unavailable until provider-backed test-clip execution exists.

### Settings → AI & Media Providers

- Add the approved AI & Media Providers destination under Settings.
- Implement AI Providers / Media Providers tab navigation.
- Render the approved provider catalogs without claiming credentials, health, readiness or usage that Kairo cannot currently verify.
- Keep provider `Manage`, `Connect`, `Add provider`, provider-settings and help actions visibly unavailable when there is no governed configuration backend/flow yet.
- Link the existing Settings surface to AI & Media Providers.
- Keep Brand navigation available when a Brand is in scope.

### Durable follow-up record

Record every approved control that still needs implementation in `docs/plans/VS-95-deferred-interactions.md`, including the dependency and the condition that will make the control safe to enable.

## Explicit non-goals

- No API, worker, migration, database, provider-adapter or credential-storage changes.
- No provider API keys, endpoints or secrets in web code.
- No fake `Connected · Healthy`, `Ready`, usage, cost or quota claims.
- No avatar media generation or test-clip execution.
- No Website re-ingestion/refresh implementation without an existing governed API contract.
- No YouTube authenticated publishing-management implementation.
- No implementation of General, Team, Billing, Notifications, Integrations, Security or Audit log; these Settings pages remain unapproved design work.
- No changes to the approved bitmap geometry of Home, Content, Calendar or Insights.
- No merge, release or deployment without later exact-SHA approvals.

## Acceptance criteria

- [ ] Brand → Channels and Brand → Avatar remain direct working routes.
- [ ] Instagram source refresh invokes the existing refresh action and returns to Brand with a truthful notice/error.
- [ ] Avatar → Back to Brand works.
- [ ] Avatar → Go to Settings opens Settings → AI & Media Providers → Media Providers with Avatar context.
- [ ] Avatar recommendation links land on actual editable fields, not dead controls.
- [ ] `Create & Save` remains the real presenter persistence action.
- [ ] Test clip is disabled/unavailable until a governed execution API exists.
- [ ] Settings home has a working link to AI & Media Providers.
- [ ] AI Providers and Media Providers tabs are routable and keyboard-accessible.
- [ ] Provider actions without a real backend are disabled and do not imply a successful connection.
- [ ] All deferred interactions are saved with implementation dependencies.
- [ ] No new secret/provider configuration is persisted in web code.
- [ ] Relevant web tests, build, governance validation and repository preflight pass before certification is requested.
