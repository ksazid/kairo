# VS-28 — Kairo Root Login & Onboarding Routing

Status: Approved and active — runtime implementation authorized outside production

## Goal
Make Kairo's current root entry the authentication entry point, remove the extra Kairo email-first hop, and route authenticated users without a Workspace to a dedicated onboarding page while preserving Auth0 as the sole credential boundary.

## Requirement IDs
- FR-01

## User-visible outcome
- Visiting `/` while signed out enters Kairo's Auth0 Universal Login immediately.
- Universal Login is expected to show the Kairo application identity, Auth0 database email/password, Google, and Apple when those connections are enabled for Kairo Web.
- Kairo itself never receives a password.
- A successful first login returns to Kairo and routes a user with no Workspace to `/onboarding`.
- A returning user with a Workspace continues to the application.
- `/sign-in` remains only as a recoverable Auth0 failure/configuration surface, not the normal login step.

## In scope
- Signed-out `/` redirect to `/auth/login`.
- Dedicated authenticated `/onboarding` route for Workspace + first Brand creation.
- Safe post-callback routing through `/` into onboarding when no Workspace exists.
- Auth0 login route accepts bounded direct social connection names for Google and Apple while the default flow remains Universal Login.
- Stable Kairo authentication logo asset suitable for Auth0 Application Logo configuration.
- Auth0 tenant follow-up documented for application-specific logo, database connection, Google and Apple.
- Preserve Authorization Code + PKCE, state, transaction cookie, audience/JWKS verification and Kairo-owned authorization.

## Non-goals
- Kairo-owned password form or Resource Owner Password Grant.
- Changing Workspace/Brand authorization semantics.
- API/database changes.
- Enabling or configuring Apple Developer credentials in this repository.
- Mutating the Auth0 tenant from CI or committed secrets.
- Building the future public marketing/pricing site.
- Production deployment, release or production enablement.

## Acceptance criteria
1. Signed-out `/` has no intermediate Kairo email prompt and starts Auth0 Universal Login.
2. Kairo does not receive, proxy, persist or log passwords.
3. Authenticated users with no Workspace are routed to `/onboarding`.
4. Workspace creation continues to the existing Brand Brain setup flow.
5. Authenticated users with a Workspace continue to the existing Kairo application.
6. Google can still be selected directly through Auth0 and Apple is a bounded supported connection name for later configuration.
7. Default `/auth/login` does not force a specific connection, allowing Auth0 Universal Login to render the enabled database/social choices.
8. A Kairo logo asset is available for Auth0 application-specific branding.
9. Auth0 tenant/Apple configuration not performed by code is called out explicitly and is not claimed complete.
10. Production remains blocked pending exact-SHA certification and separate release/production approvals.
