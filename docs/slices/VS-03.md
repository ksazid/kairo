# VS-03 — Hunter and Discover

Status: Proposed for scope approval

## Goal
Create the global-public discovery pipeline and Brand relevance layer that surfaces only worthwhile, non-duplicate Opportunities.

## Requirement IDs
- FR-06
- FR-07

## User-visible outcome
Today/Discover can show ranked Opportunities with evidence summary, Brand relevance, novelty and a concise reason why they matter now—or explicitly show no strong opportunity.

## In scope
- Global public Signal model and normalisation/deduplication.
- Per-Brand relevance scoring and Opportunity lifecycle.
- Recent-Idea/content semantic duplicate checks.
- Today/Discover Opportunity list and develop/save/ignore actions.
- Provenance, freshness and safe source metadata.
- Shared public research without leaking private Brand intelligence.
- Agent Reach as an approved, replaceable Dynamic Skill / `DiscoverySourceProvider` for public discovery, pinned to an evaluated upstream revision before promotion.
- Kairo-owned `ToolGateway` between Hermes and Agent Reach so agents receive only scoped discovery capabilities rather than unrestricted shell execution.
- Source-specific routing/fallback so official or safer providers can supersede Agent Reach per platform without changing Hunter domain logic.

## Non-goals
- Research dossiers and Angles.
- Campaign/content generation.
- Autonomous publishing.
- Enterprise social listening or unrestricted scraping.
- Direct Hermes shell access to Agent Reach or arbitrary upstream CLIs.
- Treating browser sessions, cookies or third-party credentials as Kairo domain state.
- Making Agent Reach a mandatory or irreversible Kairo dependency.

## Dependencies and gates
- VS-02 Brand context is required.
- DEC-003 must be resolved before certification of a promoted semantic provider.
- DEC-005 approves the Agent Reach provider boundary and Dynamic Skill treatment.
- Qdrant/TurboQuant benchmark is required before provider promotion.
- Hermes may be used only after its runtime spike; DirectModelRuntime remains fallback.
- Agent Reach must pass a focused provider spike covering version pinning, structured output, provenance, timeout/cancellation, bounded network access, secret isolation, source policy and provider removal/fallback before production promotion.

## Acceptance criteria
1. A Signal can be reused globally only when visibility policy permits.
2. Brand scoring never queries another Brand's private vectors.
3. Material duplicates are warned/suppressed while genuinely different Angles remain possible.
4. Every recommended Opportunity includes a user-facing reason/evidence summary.
5. The system can return no strong opportunity instead of filler.
6. Hunter/relevance AI changes have versioned evaluation evidence.
7. Agent Reach results are normalized into Kairo-owned Signal/evidence contracts with source URL, platform, retrieval time and provider provenance where available.
8. Hermes cannot bypass `ToolGateway` to execute unrestricted Agent Reach or upstream shell commands.
9. Agent Reach can be disabled/replaced without rewriting Hunter domain logic or losing authoritative Kairo state.
10. Credentials or browser-derived session material required by an upstream source are handled through approved secret/session policy and are never exposed as free-form agent context.
