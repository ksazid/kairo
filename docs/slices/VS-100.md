# VS-100 — Core Source Intelligence Adapters

## Goal

Extend the shared SourceRouter with bounded Website, GitHub, Hacker News and RSS/Substack document adapters.

## Acceptance criteria

1. Website extraction reads the requested page and a bounded, prioritized set of same-domain Brand pages without unrestricted crawling.
2. GitHub repositories normalize repository identity, description, topics, README, languages, releases, recent activity and public popularity metadata.
3. Hacker News stories, discussions and profiles normalize official API data; discussions include bounded useful comment themes and linked-article evidence where available.
4. RSS, Atom and Substack feeds normalize bounded recent entries, author, dates, tags, summaries and available body content.
5. All adapters emit `NormalizedSourceDocument` with canonical URL, content hash, provider/parser versions, provenance, confidence and warnings.
6. Each provider degrades independently and the secure HTTP/PDF adapter remains the final fallback.
7. Fetches are bounded by page/item, byte, timeout and redirect limits and treat remote content as untrusted evidence.
8. Existing discovery providers are reused or factored into shared parsing logic; no second intelligence pipeline is introduced.
9. Credential-free public providers work by default and no credential enters Brand/model context.
10. No frozen UI, publishing authority or scheduled Hunter behavior changes.

## Required evidence

- Website bounded-page selection, same-domain enforcement and partial-failure tests.
- GitHub repository extraction and rate-limit degradation tests.
- Hacker News story/discussion/profile and bounded-comment tests.
- RSS/Atom/Substack parsing, malformed-feed and bounded-entry tests.
- Router priority, generic fallback, cache and normalized provenance tests.
- Full typecheck, tests, build, governance validation and preflight.

## Release boundary

Implementation approval does not authorize certification, merge, release or production enablement.
