# VS-87 focused context

## User outcome

A user opens Content, sees only meaningful content states, opens one execution, reviews the exact current version, approves/locks it, then publishes now or schedules later without navigating through Campaign management machinery.

## Existing reusable contracts

- `getCampaigns` / `getCampaignDetail`
- `getContentReviewStatus`
- `requestContentReview`
- `approveContentVersionRequest`
- `getChannelAccounts`
- `getCalendar`
- `publishApprovedContentNow`
- `scheduleApprovedContent`
- existing carousel-review API/render lineage
- existing Reel/Video Project editing and render boundary

## Product constraints

- Keep exactly five primary destinations.
- Content primary route is user-facing `/content`; Campaign remains internal lineage.
- No new mandatory creation destination.
- Only actual channel executions appear as preview tabs.
- Exact final/rendered media must not be approximated.
- Human approval mandatory.
- Approval bound to exact immutable version/destination.
- Publish now primary after approval; Schedule for later secondary.
- Never claim Published before provider settlement.
- Presenter hidden until an eligible Brand Avatar exists.
- Technical/research/review details progressively disclosed.

## Protected boundaries

Do not change API, worker, database/migrations, auth, Meta/provider policies, tenant isolation, release workflows or deployment infrastructure.

## Verification

Run deterministic web tests first, then repository Product Intake/Security/CI. No production deployment in VS-87.
