# VS-17 focused context — Instagram Connection + Insights

## Approved outcome

Connect a Brand-owned Instagram Professional account through Meta OAuth, reuse that connection for Kairo's deterministic Instagram publishing seam, ingest exact-media provider Insights into the existing Performance Memory pipeline, and expose safe connection lifecycle controls in the Brand Performance experience.

## Requirements

FR-05, FR-15, FR-16, FR-17, FR-18, FR-20.

## Approved policy

DEC-004. No new policy decision required unless implementation discovers a material conflict with the approved credential/OAuth boundary.

## Existing seams to preserve

- `apps/worker/src/publishing-adapters.ts`: `InstagramProfessionalAdapter` already consumes numeric Instagram Professional `accountRef` and resolves a token from opaque `credentialRef`.
- `apps/worker/src/performance.ts`: provider-neutral `MetricCollector` and bounded `PerformanceCollectionWorker` already exist.
- `packages/domain/src/analytics.ts`: exact Published Post lineage, raw metric snapshots and normalized metrics are authoritative.
- `apps/api/src/analytics-postgres-store.ts`: PostgreSQL persistence preserves post/account/external ID provenance.
- `apps/web/app/brands/[brandId]/performance/page.tsx`: existing narrative Performance Intelligence surface.

## Provider model

Use Facebook Login for Business / Instagram API with Facebook Login for VS-17 to remain compatible with the existing `graph.facebook.com` publisher. Eligible destination is a linked Instagram Professional account. Multiple eligible destinations require explicit selection.

## Security invariants

- raw provider access token never enters agent/model context;
- raw provider access token never appears in API/web response, logs or domain state;
- only encrypted credential material is persisted;
- credential encryption key and Meta App Secret remain environment/infrastructure secrets;
- OAuth state is short-lived, one-time and bound to authenticated account + Brand;
- disconnect disables credential resolution immediately;
- Brand scoping is validated on every connection/selection/disconnect operation;
- Insights are provider evidence; missing values stay unavailable rather than inferred.

## Corrective provider evidence — 2026-08-16

Production-like Graph API Explorer validation against the Kairo Meta app established that the prior VS-17 OAuth scope set could authenticate the user and grant the Instagram/Page permissions but `GET /me/accounts?fields=id,name,tasks,instagram_business_account` still returned no managed Pages. After granting `business_management`, the identical request returned the `The Duke Man` Facebook Page with its linked Instagram Professional account. The Kairo Facebook Login for Business flow therefore requests and requires `business_management` for managed-Page discovery in addition to the existing VS-17 scopes.
