## Approved architecture
- Web: Next.js + React + TypeScript.
- API: Node.js + TypeScript modular monolith.
- Transport: Fastify, kept outside domain/application modules.
- Database: PostgreSQL authoritative source of truth.
- Identity: managed standards-based OIDC/OAuth behind a Kairo-owned provider-neutral adapter.
- Authorization: Kairo-owned Workspace/Brand membership records; identity-provider subject IDs are never tenant authorization by themselves.
- API contracts: typed and versioned, problem-details-compatible errors.

## Required behavior
1. Authenticated identity can establish a Kairo account boundary.
2. Owner can create an initial Workspace and Brand atomically.
3. Workspace/Brand reads and writes require server-side membership authorization.
4. Supplying another Brand identifier never grants access.
5. Kairo web shell follows the approved minimalist Design Baseline.
6. Database schema/migrations and tenant-isolation behavior are deterministic and tested.

## Runtime guardrails
- No production deployment.
- No production-enable approval.
- No Hunter, Brand Brain enrichment, generation, publishing, metrics or billing.
- No provider-specific identity code in domain modules.
- No Fastify imports in domain modules.
- No client-side trust of Workspace/Brand identifiers.
- Sensitive identity/session data must not enter logs or agent context.
