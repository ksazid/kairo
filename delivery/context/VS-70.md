# VS-70 Focused Context — Publish Now

## User outcome

After a human has approved an exact Content Version for an exact connected destination, the primary action should be **Publish now** rather than forcing the user to choose a future calendar time. Scheduling remains available for later publication.

## Existing guarantees to preserve

- Human approval is destination-specific and mandatory.
- Editing content creates a new version and requires new review/approval.
- Publishing commands are deterministic and durable.
- The worker owns external provider calls and credentials.
- Duplicate prevention, bounded retries, unknown-state reconciliation and external-post persistence stay unchanged.
- Calendar/status UI must not display a failed/queued command as published.

## Implementation boundary

Use the existing `/api/v1/brands/:brandId/campaigns/:campaignId/assets/:assetId/schedule` command-creation route. An omitted `scheduledFor` is interpreted inside `PublishingService` as an immediate request at one captured server timestamp. The worker already claims due `scheduled` commands.

The current Content Studio web form can construct a complete immediate payload for LinkedIn text. Instagram rich-media requires media URLs/items that this form does not currently supply, so VS-70 must not invent a media URL or bypass that requirement.

Stop before merge, certification, deployment, release or production enablement. Do not broaden into Instagram media transport, account-group redesign, provider changes or autonomous publishing.
