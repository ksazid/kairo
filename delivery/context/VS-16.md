## Current implementation facts
- Web currently uses Neon Managed Better Auth for credential/social login and exchanges its token into the HttpOnly `kairo_access_token` cookie.
- Kairo API already uses a provider-neutral `OidcJwtVerifier` configured by `OIDC_ISSUER`, `OIDC_AUDIENCE`, and `OIDC_JWKS_URI`.
- Web already depends on `openid-client` 6.8.4 and contains `apps/web/src/lib/oidc.ts`.
- Existing server-side API clients read `kairo_access_token`; preserving this bridge minimizes change outside identity infrastructure.
