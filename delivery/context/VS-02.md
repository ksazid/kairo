## Goal

Give every Brand an inspectable and correctable Brand Brain plus governed private knowledge sources without introducing Hunter, semantic-provider promotion, agent runtime, executable third-party skills or cross-Brand learning.

## Requirements

- FR-03 — Brand Brain.
- FR-04 — Knowledge and sources.

## Existing foundation

VS-01 provides authenticated Account/Workspace/Brand boundaries, Kairo-owned membership checks, Fastify API transport and PostgreSQL authority. VS-02 must extend those boundaries rather than create a parallel authorization model.

## Proposed domain model

### BrandBrainField

Every material field is scoped by `workspaceId` and `brandId` and records:

- stable field key/category;
- value;
- state: `inferred | confirmed | stale`;
- provenance/source references where applicable;
- version/update timestamp;
- last confirmer where user-confirmed.

Initial sections follow the approved PRD: Identity, Positioning, Audience, Voice, Content Strategy, Goals and Boundaries. Material inferred values remain visibly distinguishable from confirmed values.

### KnowledgeSource

Every private source is scoped by `workspaceId` and `brandId` and records:

- source type: `url | website | document | note | pasted | research | product`;
- title/label and provenance;
- source URI where applicable;
- lifecycle: `active | disabled | replaced | removed | quarantined | failed`;
- visibility fixed to Brand-private by default;
- content hash, content type and size where applicable;
- object-storage identifier where document support is active;
- ingestion/scan state;
- created/updated/removed timestamps;
- audit actor.

### Retrieval metadata

VS-02 may persist Brand-scoped relational retrieval metadata and source-to-derived-record links. It does **not** promote Qdrant or PgVector; DEC-003 remains a VS-03 certification decision. No unscoped private retrieval API is allowed.

## Security and privacy boundary

- Every Brand Brain/source operation re-validates authenticated Workspace/Brand access server-side.
- Possession of a Brand/source identifier is never authorization.
- Private Brand material never enters Global Intelligence by default.
- URL ingestion requires HTTP(S)-only validation plus SSRF-safe fetching before certification.
- Documents remain private, quarantined until validation/scan passes, and require type/size controls plus a malware-scanner port before they can become active knowledge.
- Object storage remains behind a private S3-compatible port; vendor selection is a deployment ADR, not VS-02 scope.
- Retrieved/source text is untrusted input and cannot grant tools, alter policy, expose secrets or change Brand scope.
- Sensitive source content is not logged by default.

## Pending policy decision

DEC-006 defines deletion propagation when a private source is removed or replaced. This decision blocks runtime implementation and certification because the PRD explicitly requires deletion/derived-memory policy and the TRD requires propagation into derived indexes/object storage.

Recommended policy:

1. remove/private-delete raw source content and object payload;
2. remove derived chunks/index entries linked only to that source;
3. retain a content-free audit tombstone for provenance/accountability;
4. preserve facts the user explicitly confirmed, because user confirmation becomes an independent authoritative Brand Brain input;
5. mark AI-inferred facts that lose all supporting sources as `stale` and exclude them from authoritative/retrieval context until reconfirmed or supported by another active source;
6. replacement creates new provenance/version links rather than silently mutating historical evidence.

## UI boundary

Brand Brain is a structured product workspace, not a developer settings screen. Initial web structure should support:

- Brand overview/identity;
- Positioning;
- Audience;
- Voice;
- Content strategy/goals;
- Boundaries;
- Knowledge sources.

Material fields use restrained status indicators such as `Confirmed`, `Inferred` and `Needs review`. Knowledge sources show source type, provenance and lifecycle. Required states: loading, empty, error, disabled/removed source, validation error and successful save. Keyboard/focus/responsive behaviour follows the approved design baseline.

The repository does not currently contain `ui-ux-pro-max`; implementation will therefore use the approved Design Baseline plus installed `ui-review` for accessibility/responsiveness/state review, without substituting an unapproved design system.
